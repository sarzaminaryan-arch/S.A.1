# شبیه‌سازی سایت زنده (Live-Site Mirror)

این پوشه «عکسِ به‌روزِ سایت زنده» داخل مخزن است تا هر ایجنت/همکار، **بدون دسترسی
به سایت**، دقیقاً بداند همین حالا چه مقاله‌ای روی sarzaminaryan.ir منتشر است:
عنوان، نامک، نوع، چکیده، تیترهای داخل متن (ساختار مقاله)، تعداد واژه، تصویر
شاخص، طبقه‌بندی‌ها، کلیدهای متا و مقادیر سئو، تعداد و پرسش‌های FAQ، لینک‌های
داخلی، هش محتوا و این‌که نسبت به مخزن چه وضعی دارد.

## فایل‌ها

| فایل | کاربرد |
|---|---|
| `registry/live-articles.json` | رجیستری کامل و ماشین‌خوان — **منبع اصلی حقیقت برای ایجنت‌ها** |
| `INDEX.md` | خلاصهٔ آخرین تطبیق و نقشهٔ راه |
| `articles-post.md` / `articles-attraction.md` / `articles-city.md` / `articles-province.md` / `articles-page.md` | فهرست خوانای هر نوع محتوا |
| `titles.md` | نمایهٔ همهٔ عنوان‌ها — پیش از ساخت محتوای تازه این‌جا چک شود تا تکراری ساخته نشود |
| `unpublished.md` | ⛔ آماده‌های مخزن که هنوز روی سایت زنده منتشر نشده‌اند (علامت‌گذاری‌شده) |
| `fix-queue.md` | صف رفع اشکال: تکراری‌ها، اختلاف‌های با مخزن، نقص‌ها |
| `reconciliation-latest.md` | گزارش آخرین تطبیق مخزن ↔ سایت |
| `CHANGELOG.md` | تغییراتی که ایجنت بین دو ممیزی روی محتوا اعمال کرده است |
| **`ROADMAP.md`** | **رودمپ مرحله‌ای رفع نقص‌ها طبق استاندارد گوگل — مسیر کار از روی این فایل جلو می‌رود** |
| **`county-article-upgrade-plan.md`** | **روش آپدیت ۱۱۷ مقالهٔ شهرستان**: سنجش → مهاجرت به قالب مستر → بریف → دادهٔ راستی‌آزمایی‌شده → گیت‌ها → تأیید مالک |
| `county-source-ledger.md` | دفتر هر شهرستان: منبع مرجع، تجربهٔ مسافران، وضعیت بدنه — با `tools/wp-agent/county_ledger.py build` ساخته می‌شود |
| `briefs/<slug>.md` | بریف هر شهرستان پیش از همکاری/بازنویسی |

> 🔌 **از ۲۰۲۶-۱۱-۱۵ دسترسی مستقیم هم هست:** ایجنت سایت را مستقیم می‌خواند و فهرست کامل محتوا را با فرمان `inventory` می‌گیرد. مقاله را فقط پیش‌نویس می‌گذارد. این شبیه‌ساز همچنان مرجع مقایسه است. سند: `docs/WP-AGENT-DIRECT-ACCESS.md`.

## قواعد الزامی ایجنت‌ها

1. **پیش از ساخت/پیشنهاد هر محتوای تازه:** عنوان و نامک را در `titles.md` و
   `registry/live-articles.json` جست‌وجو کنید. اگر عنوان/موضوع روی سایت هست،
   محتوای تکراری نسازید؛ بهبود همان مقالهٔ موجود را پیشنهاد کنید.
2. **پیش از دست‌کاری هر مقاله:** وضعیتش را در رجیستری ببینید (`repo.status`،
   `flags`، `diff_fields`) تا بدانید با مخزن فرق دارد یا نه.
3. **بعد از هر تغییری که روی محتوای زنده یا مقالات آماده اعمال می‌کنید**
   (انتشار، ویرایش، اصلاح نقص، حذف تکراری): همان تغییر را این‌جا هم ثبت کنید:
   - ورودی همان مقاله در `registry/live-articles.json` به‌روز شود (با برچسب
     `agent_updated` و تاریخ)؛
   - یک سطر در `CHANGELOG.md` همین پوشه اضافه شود.
   ثبت ایجنت «تأییدنشده» است تا ممیزی بعدی؛ در ممیزی بعدی اسنپ‌شات تازه جای آن را می‌گیرد.
4. **ممیزی دوره‌ای:** از افزونهٔ «ممیزی مقالات زنده» اسنپ‌شات + گزارش تازه
   بگیرید و این دستور را اجرا و خروجی را کامیت کنید:

```bash
python3 tools/live-site/update_live_registry.py \
  --live <live-articles-*.csv یا snapshot.json> \
  --audit <audit-report-*.csv>
```

## وضعیت مقادیر `repo.status`

- `matched_identical` — روی سایت هست و با مخزن یکی است.
- `matched_different` — روی سایت هست ولی با مخزن فرق دارد (فیلدها در `diff_fields`).
- `live_only` — روی سایت هست ولی در خط مبنای «مقالات آماده»ی مخزن نیست
  (برای ۴۸۶ شهرستان و استان‌ها طبیعی است؛ خط مبنا فعلاً فقط مقالات آماده است).
- خط مبنا در برابر سایت غایب است → در `unpublished.md` با ⛔ می‌آید.

## نکتهٔ داده

این شبیه‌سازی از CSV اسنپ‌شات افزونه ساخته شده؛ متن کامل مقاله‌ها این‌جا نیست
(برای آن، اسنپ‌شات JSON افزونه را بگیرید). هش محتوا هست تا هر تغییری در ممیزی
بعدی فوراً دیده شود.
