## ۲. معترض برای مرحلهٔ ۳ — گزارش افزونه `sa-editorial-fix`
گزینه `sa_ef_report_last` و گزارش `sa_ef_report_<run_id>` فقط از طریق داشبورد وردپرس/مالک قابل‌دریافت است (هیچ route `eval`/خواندن `wp_options` در ابزارcalar وجود ندارد).

**به مالک نیاز است:**
> نصب ZIP افزونه ← فعال‌سازی ← ابزارها ← «ترمیم یک‌بارهٔ یادداشت‌ها» ← «اعمال اصلاح» ← کپی کردن گزارش نمایش داده‌شده.

سطرهای مورد نیاز گزارش (فقط سه مورد):
```
run_id (sa_ef_report_last): <شماره-running>
changed: <تعداد> | no_change: <تعداد> | skip_drop: <تعداد> | skip_banned: <تعداد> | notes_found: <تعداد>
skip-rewrite rows (id slug): <لیست شناسه+نامک سطرهای skip-rewrite، به شکل: 287 shush, 283 dasht-azadegan, ...>
```

فهرست `skip-rewrite` دقیق است که دسته ۸ را به‌روزرسانی می‌کند و صف replace_src را می‌سازد.

## ۴. 작업을 بعدی (پس از گزارش مالک)
1. به‌روزرسانی جدول رودمپ (دسته ۷ → ۰، دسته ۸ از تعداد skip-rewrite) + کامیت فارسی.
2. ساخت Batch ۱ با `tools/wp-agent/build_replace_batch.py` (حجم محتوای حفظ شده، ۰ یادداشت باقی نماند، Kick Checks اجرا شود).

4. پس از اجرا: تست هر صفحه = هش محتوا + صفر یادداشت + `fetch_page`.
5. به‌روزرسانی رودمپ و ادامه Batch ۲.
