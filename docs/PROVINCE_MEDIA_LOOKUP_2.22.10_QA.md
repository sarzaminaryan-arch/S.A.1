# رفع قاب سفید شناسنامه — ۲٫۲۲٫۱۰

## گزارش مالک و علت

مالک قاب مناسب ولی سفید و وجود فایل `https://sarzaminaryan.ir/wp-content/uploads/2026/10/alborz.webp` در کتابخانه را گزارش کرد. سایت/DB زنده از این محیط بررسی نشده است، اما یک خطای قطعی در کد قبلی تشخیص و بازتولید شد که رسانهٔ عادی را همیشه رد می‌کرد.

SQL به‌درستی وضعیت ذخیره‌شدهٔ پیوست را `inherit` انتخاب می‌کرد، اما بعد از گرفتن ID، PHP نتیجهٔ `get_post_status($id)` را نیز با `inherit` مقایسه می‌کرد. WordPress این تابع را برای attachment به وضعیت والد یا `publish` (پیوست بدون والد) تبدیل می‌کند. پس حتی رسانهٔ سالم با نام دقیق هم از کنترل عبور نمی‌کرد.

[تابع واقعی در WordPress core، نسخهٔ ثابت](https://github.com/WordPress/WordPress/blob/97a9c802eccee214a5884e380446c5cd25d2dd77/wp-includes/post.php).

## اصلاح و آزمون

- بررسی وضعیت ذخیره‌شده با `get_post_field('post_status', $id, 'raw')` انجام می‌شود؛ مقایسه با inherit اکنون معنی صحیح دارد.
- کنترل مستقل وضعیت منتشرشده و گذرواژهٔ والد دست‌نخورده است؛ تبدیل خودکار inherit موجب نمایش پیوست والد خصوصی/پیش‌نویس نمی‌شود.
- نام دقیق، MIME، فایل خواندنی، URL رسانه و قاب خالی برای فایل ناموجود همچنان برقرارند. هیچ نشانی hardcode و هیچ فایل/متا/عنوان رسانه تغییر نکرده است.
- آزمون ۲٫۲۲٫۹ اشتباه بود: shim به‌جای رفتار واقعی core، وضعیت خام را برمی‌گرداند. اکنون تابع اصلی get_post_status از commit ثابت بالا به‌صورت بدون تغییر در `tests/fixtures/wp-get-post-status.php` قرار دارد؛ دارای انتساب و مجوز GPL است و فقط آزمون آن را بارگذاری می‌کند، نه bootstrap قالب.
- اجرای آزمون با رفتار واقعی core روی کد قبلی شکست را بازتولید کرد؛ همان آزمون پس از اصلاح موفق شد. پیوست بدون والد با raw=inherit/resolved=publish و پیوست دارای والد منتشرشده هر دو پوشش دارند؛ کنترل private/password، نام بزرگ/-1، MIME اشتباه، نبود فایل و نبود تصویر بزرگ تکراری نیز آزموده می‌شوند.
- این تست همچنان standalone است؛ استفاده از تابع واقعی core جای اثبات اتصال زنده به DB یا سازگاری همهٔ افزونه‌های سایت نیست.
- چیدمان/CSS، نسبت ۲:۱، ابعاد پیشنهادی و scope فقط تهران/البرز از ۲٫۲۲٫۹ هیچ تغییری ندارند. افزونهٔ قبلی به به‌روزرسانی نیاز ندارد.

## تحویل و پذیرش

نسخهٔ سه‌گانهٔ قالب ۲٫۲۲٫۱۰ برای cache-busting. محلی ۱۸ آزمون PHP قالب، آزمون افزونهٔ تصاویر و تست Node موفق؛ CI [39087138185](https://github.com/sarzaminaryan-arch/S.A.1/actions/runs/39087138185) شامل lint و تست رسانه با تابع واقعی core در ۲۳ ثانیه موفق شد.

ریلیز غیرپیش‌نویس [۲٫۲۲٫۱۰](https://github.com/sarzaminaryan-arch/S.A.1/releases/tag/sarzaminaryan-child-v2.22.10) از `75b2368` منتشر و Latest شد؛ ZIP `652137448` برابر 26,429,992 بایت و checksum `652137449` در وضعیت uploaded تأیید شدند. hash تگ‌های تاریخی ۲٫۲۲٫۲/۲٫۲۲٫۹ تغییر نکرد. هیچ نصب یا تغییر دادهٔ سایت زنده انجام نشده است.

پس از نصب ZIP تازه و پاک‌کردن کش صفحه/CDN، البرز را با همان رسانهٔ موجود باز کنید؛ لازم نیست عکس را دوباره بارگذاری یا نامش را عوض کنید. اگر بعد از این رفع همچنان قاب سفید ماند، وضعیت واقعی `_wp_attached_file`/MIME/مسیر فایل/والد روی هاست باید از راه دسترسی مجاز مدیر بررسی شود؛ این نسخه برای عبور از کنترل‌ها از URL حدسی یا تصویر شاخص نامرتبط استفاده نمی‌کند.
