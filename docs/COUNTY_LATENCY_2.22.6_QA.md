# پیگیری تأخیر شهرستان — ۲٫۲۲٫۶

تاریخ: ۲۰۲۶-۱۰-۱۸ · شاخه: `arena/a32fb27a-s-a-1`

## وضعیت گزارش زنده

مالک پس از تحویل ۲٫۲۲٫۵ گفت تبریز و همهٔ شهرستان‌ها همچنان حدود ده ثانیه
دیر باز می‌شوند؛ نمونه: https://sarzaminaryan.ir/city/tabriz/ . سؤال تأیید نسخهٔ
نصب‌شده/پاک‌سازی کش هنوز پاسخ ندارد. **۲٫۲۲٫۵ مشکل گزارش‌شده را حل‌شده محسوب
نمی‌کنیم.** هیچ زمان زنده، SQL slow log، EXPLAIN یا دسترسی به هاست نداریم.

## یافته و اصلاح SQL

`sa_county_related_articles()` کوئری OR/AND چندلایه روی province_id و
sa_province_id، شرط NOT EXISTS/خالی، دو مقایسهٔ عددی و ORDER BY RAND داشت.
ساختار meta_query وردپرس برای چنین شرط‌هایی چند self/LEFT JOIN به postmeta
می‌سازد؛ این مسیر به همهٔ صفحات شهرستان اضافه شده است. هزینهٔ واقعی آن روی
دیتابیس مالک اندازه‌گیری نشده؛ این یافته هنوز اثبات علت ده ثانیه نیست.

- `cc47650`: خواندن فقط دو کلید رابطه، فقط شهرستان‌های publish، با **یک**
  INNER JOIN مثبت؛ بدون OR/NOT EXISTS/CAST یا RAND. ردیف‌ها به ترتیب meta_id
  خوانده می‌شوند؛ اولین مقدار هر کلید مطابق get_post_meta اولویت دارد.
- province_id غیرخالی بر legacy مقدم است؛ legacy فقط هنگام خالی/نبودن کلید
  کانونی استفاده می‌شود. استان صفر، منفی و نامعتبر، شهرستان جاری و هم‌استانی
  وارد نامزدها نمی‌شوند. شرط «استان شناخته‌شده» در این مسیر یعنی رابطهٔ عددی
  مثبت؛ وجود/وضعیت انتشار خود پست province با SQL جدید جداگانه اعتبارسنجی نمی‌شود.
- نامزدها در PHP shuffle می‌شوند؛ WP_Query نهایی با post__in/ORDER BY FIELD
  فقط سه شهرستان منتشرشده را با فیلترهای معمول وردپرس می‌خواند. خالی‌بودن
  نامزدها پیش از WP_Query کنترل می‌شود تا post__in=[] همهٔ مطالب را برنگرداند.
- دو کوئری اصلی داریم: روابط و سه کارت؛ خود وردپرس/افزونه‌ها ممکن است برای
  کش متا/تکسونومی کوئری‌های دیگری بزنند. سقف مصنوعی برای تعداد نامزدها نداریم،
  ولی با افزایش شهرستان‌ها تعداد JOINها ثابت می‌ماند و فقط سه کارت hydrate می‌شود.
- کش پایدار تازه‌ای برای روابط ساخته نشده؛ تغییر وضعیت انتشار/رابطه بلافاصله
  در درخواست بعدی دیده می‌شود و خطر invalidation ناقص نداریم. کش صفحهٔ بیرونی
  همچنان باید پس از نصب پاک شود.

## زمان‌سنج خصوصی، نه یادداشت مقاله

`7313f66`: پیشخوان ← ابزارها ← **زمان‌سنج شهرستان**.

۱. با حساب مدیر دارای manage_options، تبریز را باز کنید و تا پایان بارگذاری
صبر کنید؛ سپس صفحهٔ ابزار را باز/تازه‌سازی کنید.
۲. JSON آخرین نمونهٔ خودتان را در گفتگو بفرستید. theme_version باید 2.22.6،
county_id باید شهرستان مورد نظر و captured_at_utc باید زمان همین بازدید باشد.
۳. در صورت تداوم تأخیر، علاوه بر این گزارش، زمان Waiting/TTFB درخواست اصلی
Document در Network مرورگر را بدهید؛ زمان بارگذاری iframe نقشه با آن متفاوت است.

نمونه فقط برای مدیر واردشده، فقط صفحهٔ city و نه پیشخوان/خوراک/REST ثبت می‌شود؛
یک transient کوچک مختص هر مدیر تا ۱۵ دقیقه باقی می‌ماند و با نمونهٔ بعدی جایگزین
می‌شود. مهمان هیچ نمونه/نوشتن transient ندارد. SQL، کوکی، توکن، پارامترهای URL،
مسیر فایل یا متن مقاله ذخیره نمی‌شود؛ صفحهٔ ابزار هم کنترل دسترسی و escape دارد.
محتوای عمومی، هدرها و مقالهٔ دیده‌شده حتی برای مدیر هیچ گزارش یا یادداشتی نمی‌گیرند.

معنی کلیدها:

| کلید | محدوده |
|---|---|
| php_to_shutdown_ms | از شروع PHP تا hook shutdown، نه صف وب‌سرور/CDN و شبکهٔ مرورگر |
| after_wp_ms | از hook wp تا همان shutdown |
| before_template | شروع PHP تا پایان template_redirect؛ شامل bootstrap، افزونه‌ها و query اصلی |
| identity | رندر شناسنامه/مشخصات کلی شهرستان |
| rating | رندر بخش امتیازدهی |
| map_gallery | خروجی نقشه و گالری سمت سرور، نه دانلود iframe در مرورگر |
| content_filters | اجرای بیرونی فیلتر the_content؛ فراخوانی بازگشتی مدت بیرونی را قطع نمی‌کند |
| related_relations | خواندن SQL روابط |
| related_cards | query نهایی و رندر کارت‌ها |
| related_total | کل مسیر مرتبط، شامل دو مرحلهٔ بالایی و انتخاب PHP |
| navigation / sources | رندر قبلی/بعدی و منابع |
| db_queries_after_wp | شمار کوئری‌ها بعد از wp؛ نه شمار کل bootstrap |

زمان‌های تودرتو را جمع نکنید؛ همهٔ قالب/افزونه‌ها به‌صورت جداگانه instrument
نشده‌اند و زمان باقی‌مانده می‌تواند در header/footer، پاک‌سازی نهایی مقاله،
افزونه یا shutdown باشد. پاسخ full-page cache که PHP را اجرا نکند نمونهٔ جدید
نمی‌سازد؛ زمان/نسخهٔ گزارش قدیمی را با درخواست تازه اشتباه نگیرید. زمان ذخیرهٔ
خود transient و hookهای بعدی shutdown در php_to_shutdown_ms نیست.

## آزمون و محدودیت نتیجه

- `test-county-related-performance.php` ابتدا روی کد قبلی با خطای الزامیِ
  «No multi-join meta_query» شکست خورد؛ پس از اصلاح موفق شد.
- کنترل شکل SQL (یک JOIN، فقط کلیدهای مربوط، فقط city/publish)، یک query روابط
  و یک WP_Query کارت، اولویت canonical/legacy/اولین متا، حذف هم‌استانی/نامعلوم،
  لیست خالی، عدم کش منقضی رابطه و نمونهٔ هزار شهرستان با ۵۰۰ نامزد بررسی شد.
- `test-county-performance.php`: مهمان/نقش غیرمجاز/استان/REST/feed/admin بدون
  ثبت، مجوز ابزار، TTL و جداسازی کاربر، escape گزارش، زمان‌های مرحله‌ای، شمار
  کوئری و عدم تغییر بایت‌های محتوای مقاله؛ فیلتر بازگشتی هم آزمایش شد.
- هر ۱۶ آزمون مستقل و parse هر ۱۴۴ فایل PHP روی PHP-WASM 8.5.10 موفق بود؛
  دو تست جدید وارد CI شدند. اعداد این fixtureها زمان دیتابیس یا سایت واقعی نیستند.
- parent، wp-config، افزونه، دادهٔ مقاله و مقیاس ذخیرهٔ رأی تغییر نکردند؛ هیچ
  PR/merge یا تغییر تگ تاریخی صورت نگرفته است. تنها نوشتن جدید روی نصب زنده،
  transient موقت گزارش خصوصی برای بازدیدِ مدیر است؛ هیچ migration داده نداریم.
