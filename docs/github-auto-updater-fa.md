# راهنمای اتصال قالب فرزند به GitHub Auto-Updater

این راهنما مربوط به قالب `sarzaminaryan-child` و مخزن زیر است:

- مخزن: <https://github.com/sarzaminaryan-arch/S.A.1>
- پیشوند انتشارهای قالب: `sarzaminaryan-child-v`
- نام فایل هر انتشار: `sarzaminaryan-child-vX.Y.Z.zip`

> مخزن خصوصی است؛ بنابراین هر وردپرس برای دیدن نسخه‌ها و دریافت فایل انتشار به یک GitHub token فقط‌خواندنی نیاز دارد. هیچ توکنی در قالب، ZIP یا مخزن قرار داده نشده است.

## ۱. نصب اولیه (فقط یک‌بار)

نسخهٔ 2.3.1 نخستین نسخه‌ای است که به‌روزرسان داخلی دارد. پس این نسخه باید یک‌بار به‌صورت دستی نصب شود:

1. فایل `sarzaminaryan-child-v2.3.1.zip` را از Release گیت‌هاب دانلود کنید.
2. در وردپرس به «نمایش ← پوسته‌ها ← افزودن پوسته ← بارگذاری پوسته» بروید.
3. ZIP را انتخاب کنید و در صورت سؤال وردپرس، جایگزینی نسخهٔ فعلی را تأیید کنید.
4. قالب فرزند باید فعال بماند؛ قالب والد `sarzaminaryan` نیز باید نصب باشد.

از نسخه‌های بعدی، نصب از «پیشخوان ← به‌روزرسانی‌ها» انجام می‌شود.

## ۲. ساخت توکن امن در گیت‌هاب

روش پیشنهادی، **Fine-grained personal access token** است:

1. در حسابی که به مخزن دسترسی دارد، صفحهٔ <https://github.com/settings/personal-access-tokens/new> را باز کنید.
2. برای Repository access گزینهٔ «Only select repositories» و سپس `S.A.1` را انتخاب کنید.
3. در Repository permissions، فقط `Contents: Read-only` را فعال کنید؛ `Metadata: Read-only` به‌صورت خودکار فعال است.
4. تاریخ انقضای مناسب انتخاب و توکن را ایجاد کنید.
5. توکن را فقط در سرور وردپرس نگه دارید. آن را در گیت‌هاب، کد قالب، تیکت یا گفت‌وگو نفرستید.

اگر توکن منقضی یا لغو شود، سایت از کار نمی‌افتد؛ فقط بررسی/دریافت به‌روزرسانی تا ثبت توکن جدید متوقف می‌شود.

## ۳. اتصال وردپرس به مخزن

### روش A — پیشنهادی: `wp-config.php`

با File Manager سی‌پنل، پیش از خط `/* That's all, stop editing! */` این مقدار را قرار دهید:

```php
define( 'SA_GITHUB_TOKEN', 'github_pat_xxxxxxxxxxxx' );
```

مقدار نمونه را با توکن واقعی جایگزین کنید. مزیت این روش این است که توکن در جدول تنظیمات وردپرس ذخیره نمی‌شود و با به‌روزرسانی قالب نیز تغییر نمی‌کند.

### روش B — از پیشخوان

1. به «نمایش ← به‌روزرسان گیت‌هاب» بروید.
2. توکن را در فیلد `GitHub Token` وارد کنید.
3. «ذخیرهٔ تنظیمات» را بزنید.
4. وضعیت باید «ارتباط برقرار است» و شمارهٔ آخرین نسخه را نشان دهد.

فیلد توکن پس از ذخیره عمداً خالی نمایش داده می‌شود و مقدار محرمانه هرگز دوباره در HTML صفحه چاپ نمی‌شود. اگر روش A فعال باشد، ثابت `SA_GITHUB_TOKEN` بر مقدار ذخیره‌شده در دیتابیس اولویت دارد.

## ۴. دریافت به‌روزرسانی با یک کلیک

1. در «نمایش ← به‌روزرسان گیت‌هاب»، «بررسی هم‌اکنون» را بزنید؛ یا به «پیشخوان ← به‌روزرسانی‌ها» بروید.
2. اگر شمارهٔ Release جدیدتر از نسخهٔ موجود در `style.css` باشد، قالب در فهرست به‌روزرسانی‌ها ظاهر می‌شود.
3. قالب را انتخاب و «به‌روزرسانی پوسته‌ها» را بزنید.
4. وردپرس فایل Release را با احراز هویت دریافت می‌کند، ZIP و SHA-256 اعلام‌شده را بررسی می‌کند و سپس قالب را جایگزین می‌کند.

نتیجهٔ بررسی Release تا ۶ ساعت کش می‌شود. دکمهٔ «بررسی هم‌اکنون» این کش و کش استاندارد به‌روزرسانی وردپرس را پاک می‌کند.

## ۵. اتصال اکانت‌ها یا سایت‌های دیگر

برای هر نصب وردپرس:

1. همین ZIP راه‌انداز (2.3.1 یا جدیدتر) را یک‌بار نصب کنید.
2. یک توکن Fine-grained با دسترسی فقط‌خواندنی به `S.A.1` بسازید. حساب سازندهٔ توکن باید خودش به مخزن خصوصی دسترسی داشته باشد.
3. توکن را با یکی از دو روش بالا در همان سایت تنظیم کنید.
4. «بررسی هم‌اکنون» را بزنید.

می‌توان یک توکن را روی چند سایت تحت مدیریت یک مالک استفاده کرد، اما برای جداسازی امنیتی و لغو مستقل، توکن جدا برای هر سرور بهتر است. اگر قرار است به کاربران فاقد دسترسی GitHub به‌روزرسانی داده شود، باید مخزن/Release عمومی شود یا یک سرویس توزیع دارای مجوز جداگانه ساخته شود.

## ۶. فرایند انتشار نسخه‌های بعدی برای ایجنت/توسعه‌دهنده

Workflow فایل `.github/workflows/release-child-theme.yml` با هر Push مرتبط به قالب روی `main` یا شاخه‌های `arena/**` اجرا می‌شود:

1. شمارهٔ نسخه را هم در `style.css` و هم در `SA_CHILD_VERSION` داخل `functions.php` افزایش دهید.
2. `CHANGELOG.md` و `readme.txt` را به‌روز کنید.
3. تغییرات را Push کنید.
4. GitHub Actions همهٔ فایل‌های PHP را lint می‌کند، نبود توکن واقعی را بررسی می‌کند و ZIP استاندارد با یک پوشهٔ ریشهٔ `sarzaminaryan-child/` می‌سازد.
5. Release با تگ `sarzaminaryan-child-vX.Y.Z`، فایل ZIP و فایل `.sha256` ایجاد می‌شود.
6. وردپرس‌ها در بررسی بعدی همان Release را می‌بینند.

اگر کد قالب با همان شمارهٔ نسخهٔ منتشرشده دوباره تغییر کند، Workflow عمداً خطا می‌دهد. در نتیجه **هر Push انتشارپذیر باید افزایش نسخه داشته باشد**؛ صرف Push بدون نسخهٔ جدید نباید باعث جایگزینی مبهم فایل‌های کاربران شود.

## ۷. خطاهای رایج

- **HTTP 401/403/404:** توکن نامعتبر/منقضی است، یا به مخزن `S.A.1` دسترسی ندارد.
- **ارتباط با API برقرار نشد:** سرور باید اتصال HTTPS خروجی به `api.github.com` داشته باشد.
- **دانلود Release انجام نشد:** علاوه بر `api.github.com`، دامنه‌های `github.com` و `*.githubusercontent.com` نباید در فایروال مسدود باشند.
- **به‌روزرسانی نمایش داده نمی‌شود:** دکمهٔ «بررسی هم‌اکنون» را بزنید و مطمئن شوید شمارهٔ Release واقعاً از نسخهٔ نصب‌شده بیشتر است.
- **SHA-256 ناسازگار:** نصب برای امنیت متوقف می‌شود؛ فایل Release نباید پس از انتشار جایگزین شود و باید نسخهٔ تازه‌ای منتشر شود.
