# گزارش پیشرفت ممیزی SEO — نسخهٔ ۱٫۹

**تاریخ:** ۲۰۲۶-۱۰-۱۶
**دامنه:** تطبیق کامل inventory + WXR + crawl HTML موجود؛ بررسی معماری و لینک‌های داخلی؛ ارتقای ایمنی exporter.
**وضعیت سایت:** فقط تحلیل. هیچ تغییر، تعمیر یا انتشار روی سایت زنده انجام نشده است.

## خلاصهٔ اجرایی

- سه ورودی Drive با هم تطبیق داده شدند: inventory، crawl رندرشده و WXR. همهٔ 622 رکورد منتشرشدهٔ پنج نوع اصلی در inventory/WXR از نظر ID، slug، URL و تاریخ انتشار/ویرایش منطبق‌اند؛ اختلاف صفر.
- Crawl کامل 692/692 URL است: 655 پاسخ 200، 33 redirect بدون دنبال‌کردن و 4 timeout. Redirect/timeoutها status قطعی 404 نیستند و باید در crawl بعدی از شبکهٔ پایدار بازآزمایی شوند.
- 617 صفحهٔ محتوایی با status 200، همگی title، canonical، H1 و JSON-LD دارند؛ canonicalها دقیقاً با URL درخواست‌شده منطبق‌اند؛ 616/617 meta description دارند. `/blog/` تنها مورد فاقد description است.
- شکاف شهرستان→جاذبه از روی HTML زنده تأیید شد: از 20 شهرستان دارای جاذبهٔ فرزند، 10 صفحه هیچ لینک مستقیم به جاذبه‌های فرزند ندارند.
- شمار baseline 483 شهرستان در برابر 487 صفحهٔ زنده تطبیق شد: 482 نامک مشترک، پنج مورد live-only و یک مورد baseline-only. `dorud` در برابر `dorud-city` جایگزینی محتمل است؛ قطعی نیست.
- در متن ذخیره‌شده 8,361 لینک داخلی query-free به 589 مقصد یکتا وجود دارد؛ 91 رخداد به 17 مقصد خارج از manifest crawl می‌روند. این مقصدها هنوز HTTP-check نشده‌اند؛ broken بودنشان ثابت نشده است.
- Crawl قبلی با افزونهٔ 1.1.0 در context مدیر اجرا شده و لینک‌های admin و query موقت در خروجی خام دارد. پوشهٔ Drive هنگام بررسی فقط به مالک دسترسی داشت. هیچ مقدار nonce یا اطلاعات شخصی نویسنده بازنشر نمی‌شود؛ فایل خام را عمومی نکن.
- سورس exporter به 1.2.0 ارتقا یافته: fetch HTML ناشناس بدون cookie مدیر، حذف query/fragment از نمونه‌های لینک و فیلتر مسیرهای admin/login. شمار alt attribute از alt خالی جدا شده است. `node --check` و `git diff --check` موفق‌اند؛ ZIP ساخته و integrity/source match آن تأیید شد. PHP lint به‌علت نبود PHP CLI و آزمون WordPress runtime به‌علت نبود محیط سایت انجام نشده است.

### Crawl و SEO on-page

- 692 URL از 692 URL ثبت‌شده crawl شده‌اند؛ خروجی truncation ندارد.
- 655 HTTP 200، 33 redirect (crawler دنبال نکرده)، 4 timeout.
- Redirectها: 31 آرشیو taxonomy استان، `/wp-sitemap.xml` و صفحهٔ شهرستان `ijrud`. مقصدهای redirect در این snapshot ثبت/دنبال نشده‌اند.
- Timeoutها: `/city/lenjan/`, `/city/abadan/`, `/city/komijan/`, `/city/zebarkhan/`.
- 617 صفحهٔ محتواییِ HTTP 200: 617 title یکتا، 617 canonical یکتا و مطابق URL، 617 یک H1، 617 دارای JSON-LD، 616 meta description یکتا. مورد استثنا: `/blog/` description ندارد.
- 617 صفحه `index,follow` دارند؛ 11 آرشیو tag، `noindex,follow` هستند. این‌ها وضعیت رندر است، نه گزارش ایندکس Google.
- `/route/`, `/food/`, `/souvenir/` سه archive 200 با صفر رکورد منتشرشده و حدود 42–44 واژه متن‌اند؛ هر سه indexable هستند. توصیه: تصمیم editorial دربارهٔ افزودن محتوای واقعی یا noindex، با تأیید مالک.
- Sitemap index اصلی 200 و شامل هشت sitemap فرزند است؛ sitemap جاذبه شامل 29 URL. `/wp-sitemap.xml` redirect است، اما sitemap اصلی سالم دیده شد.
- robots.txt جستجو را مجاز و برای برخی crawlerهای AI/آموزشی محدودیت تعریف می‌کند. به‌عنوان policy ثبت شود؛ شواهد این crawl نشان نمی‌دهد Googlebot عمومی مسدود باشد.

### لینک‌سازی و خوشه‌ها

1. 31 صفحهٔ استان در مجموع به هر 487 شهرستان مرتبط لینک دارند (توزیع‌شده بر اساس استان والد).
2. هر 29 جاذبه در خروجی خودش به والد شهرستان و استان لینک می‌دهد و metadata والد دارد.
3. از 20 شهرستان دارای جاذبهٔ فرزند، 10 شهرستان همهٔ جاذبه‌های فرزند را لینک می‌کنند و 10 شهرستان هیچ لینک مستقیم ندارند: Khorramabad، Amol، Kuhrang، Qeshm، Isfahan city، Kashan، Kerman، Tabas، Garmsar، Boshruyeh. این شکاف تأییدشده، P1، و نیازمند تأیید جداگانه پیش از تعمیر است.
4. لینک‌های داخلی ذخیره‌شده: 8,361 رخداد/589 مقصد یکتا؛ 8,239 رخداد مقصد 200 crawl‌شده، 30 رخداد مقصد timeout، یک رخداد مقصد redirect، و 91 رخداد در 17 مقصد خارج از manifest. «خارج از manifest» به‌تنهایی به معنی broken نیست.
5. چهار هدف خارج از manifest پرتکرار: `/city/dorud` (43)، `/editorial-policy` (17)، `/city/talqan` (8)، `/city/sojablogh` (8). صفحهٔ زندهٔ دورود نامک `dorud-city` دارد و صفحهٔ سیاست تحریریه در inventory `/policy/` است؛ ممکن است alias/redirect باشند. status مسیرهای قدیمی هنوز نامعلوم است.
6. 17,572 رخداد لینک خارجی به 331 hostname ثبت شد؛ اعتبار/status مقصد خارجی بررسی نشده است.

### ایمنی داده و exporter

Crawl 1.1.0 در حالت ورود مدیر اجرا شده است؛ خروجی خام شامل نشانگرهای حالت admin و URLهای admin/query موقت بود. Drive folder هنگام بررسی فقط permission مالک را داشت. مقدار nonce در گزارش، commit یا پاسخ بازنشر نمی‌شود. کپی‌های خام دانلودشده از workspace پس از تحلیل حذف شدند؛ فایل‌های اصلی Drive دست‌نخورده‌اند و خصوصی بمانند. فایل WXR نیز metadata نویسنده دارد؛ در گزارش هیچ اطلاعات شخصی نویسنده نیست.

نسخهٔ سورس 1.2.0:
- درخواست صفحه با `credentials: 'omit'`؛
- حذف لینک‌های دارای query/fragment از نمونه‌های ذخیره‌شده؛
- فیلتر `/wp-admin`, `/wp-login.php`, `/wp-signup.php`, `/wp-cron.php`؛
- خروجی schema به `sa-rendered-audit-v2` و تفکیک تصویر بدون alt attribute از alt خالی؛
- نسخه/README به‌روز شده و یادآوری خصوصی‌بودن crawl 1.1.0.

PHP CLI در sandbox نصب نیست و سایت زنده از محیط قابل فراخوانی نیست؛ بنابراین `php -l` و آزمون runtime روی WordPress انجام نشده‌اند. `node --check`، `git diff --check` و integrity/source match فایل ZIP موفق‌اند. پیش از نصب روی سایت، lint PHP و آزمون runtime باید در CI یا staging مدیر انجام شوند.

## ترتیب بعدی

1. منبع و ZIP نسخهٔ 1.2.0 را در branch همین session ثبت و push کن؛ PHP lint/runtime روی staging فقط با تأیید مالک انجام شود.
2. برای 4 timeout، 33 redirect، 17 مقصد داخلی خارج از manifest و پنج URL شهرستان بدون status روشن، یک crawl هدفمندِ بی‌کوکی با URLهای صریح بساز؛ خروجی عادی exporter فقط manifest وردپرس را می‌خواند، پس ابزار/manifest تکمیلی لازم است. URLهای queryدار/admin خارج بمانند.
3. جدول 20 شهرستان دارای جاذبه را به‌عنوان issue تأییدشده حفظ کن؛ هیچ repair در سایت تا تأیید مالک انجام نشود.
4. تصمیم editorial برای سه archive خالی و بازبینی JSON-LD کامل صفحات static (نوع `BlogPosting` در هر 8 صفحه دیده شد، ولی node کامل هنوز بررسی نشده).
5. ممیزی جزءبه‌جزء 29 جاذبه و تطبیق ماتریس 80 شاخص → 38 آماده → 29 منتشرشده.
6. نسخهٔ بعدی گزارش پیشرفت و changelog بعد از هر مرحله به‌روزرسانی شود.
