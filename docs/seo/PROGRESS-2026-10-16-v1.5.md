# گزارش پیشرفت ممیزی — نسخهٔ ۱٫۵

- **موضوع:** اتصال به سایت زنده و راه امن دریافت دادهٔ ممیزی.
- **وضعیت اتصال:** در این محیط، دسترسی خروجی فقط به چند میزبان مشخص (از جمله GitHub) محدود است و `sarzaminaryan.ir` در فهرست مجاز نیست. بنابراین از محیط تحلیل درخواست مستقیم به سایت ارسال نکردم و اتصال را تأییدشده اعلام نمی‌کنم.
- **راه جایگزین ساخته‌شده:** افزونهٔ WordPress فقط‌خواندنی **SA Site Audit Exporter 1.0.0** در `tools/sa-site-audit-exporter/`.
- **اثر روی سایت:** افزونه هنوز توسط مالک نصب/اجرا نشده؛ از سمت ما هیچ اتصال، تغییر محتوا یا تغییر دیتابیس در سایت زنده انجام نشده است.

## خروجی افزونه

### فایل اول: فهرست عمومی محتوا

از **ابزارها ← خروجی ممیزی سایت**، دکمهٔ «ساخت و دریافت فهرست محتوا (JSON)» را بزنید. خروجی شامل رکوردهای منتشرشدهٔ عمومی (تا سقف 5000) است: post type، عنوان، URL، نامک، تاریخ انتشار/ویرایش، excerpt و متن ذخیره‌شده، آمار ساختاری ساده، پیوندهای موجود، taxonomyهای عمومی و allowlist محدود متادیتای SEO/روابط.

این فایل برای تحلیل وضعیت وردپرس و رابطه‌های ذخیره‌شده مفید است؛ اما به‌تنهایی HTML داینامیک قالب را نشان نمی‌دهد.

### فایل دوم: نمونهٔ HTML واقعی در سایت

همان صفحه، «شروع بررسی HTML زنده» را اجرا کنید. مرورگر مدیر به‌ترتیب به همان سایت و فقط از همان origin درخواست GET می‌فرستد؛ نمونه شامل `robots.txt` و چند نشانی رایج sitemap، صفحهٔ اصلی، آرشیوهای عمومی، استان‌ها و جاذبه‌های منتشرشده، یک شهرستان منتشرشده برای هر استان (در صورت وجود)، و حداکثر پنج نوشتهٔ آموزشی است. redirect دنبال نمی‌شود تا حتی تغییرمسیر خارجی نیز درخواست بعدی به دامنه‌ای دیگر نسازد؛ درخواست بیرونی/ارسال داده به سرور دیگری وجود ندارد.

خروجی دوم summary صفحه را می‌دهد: HTTP status یا نشانگر redirect دنبال‌نشده، title، meta description، canonical، robots، زبان/جهت، H1/H2، JSON-LD types، breadcrumb، شمار واژه و مقصد لینک‌های داخلی. HTML کامل در فایل ذخیره نمی‌شود.

## حریم خصوصی و کنترل

- تنها مدیر با `manage_options` می‌تواند خروجی بگیرد؛ فرم POST nonce دارد.
- فقط محتوای `publish` از post type عمومی؛ پیش‌نویس/خصوصی، دیدگاه، سفارش، کاربر و همهٔ metaها جمع نمی‌شوند.
- هیچ API خارجی، analytics یا upload خودکار استفاده نمی‌شود. فایل‌ها فقط در مرورگر مدیر دانلود می‌شوند.
- قبل از پیوست، فایل‌ها را بازبینی کنید؛ هر اطلاعاتی که روی صفحهٔ عمومی سایت است ممکن است در محتوای منتشرشده باشد.
- بعد از دانلود می‌توانید افزونه را غیرفعال و حذف کنید؛ دادهٔ جمع‌آوری‌شده در سایت ذخیره نمی‌شود.

## بررسی فنی محلی

- parser سازگار با PHP 7.4، syntax فایل افزونه را parse کرد.
- `node --check` برای اسکریپت crawler موفق بود.
- `git diff --check` موفق بود.
- مفسر PHP در sandbox نصب نیست، بنابراین `php -l` واقعی اجرا نشد. تست روی سایت واقعی نیز تا زمان نصب مالک انجام‌شدنی نیست.

## گام بعدی برای مالک

1. ZIP افزونه را از انتشار GitHub نصب کنید (افزونهٔ عادی وردپرس؛ نه کد قالب).
2. هر دو JSON را دریافت کنید.
3. فایل‌ها را در همین گفت‌وگو پیوست کنید؛ اگر حجم بالا بود، ابتدا هر کدام جداگانه بفرستید.
4. من از فایل اول شمار و وضعیت live/روابط/SEO را با snapshot مخزن تطبیق می‌دهم و از فایل دوم خروجی واقعی template، sitemap/indexability نمونه‌ها و مسیر لینک‌ها را تحلیل می‌کنم.
5. بعد گزارش معماری و ایرادهای 🔴/🟠/🟡 را تکمیل می‌کنم؛ هیچ repair تا تأیید جداگانه انجام نمی‌شود.
