# نقشهٔ راه «شناسنامهٔ ثابت شهرستان»

سند فنی مخزن است (نه متن صفحهٔ بازدیدکننده). «شناسنامه» یک کارت جمع‌وجور، ثابت و
سایبری/تکنولوژیک در بالای هر یک از ۴۸۳ نوشتهٔ `city` (شهرستان) است و جای مقالهٔ بلندِ
پر از عدد را می‌گیرد: همهٔ رقم‌ها فقط داخل کارت می‌آیند و بدنهٔ مقاله کار روایت و سفر می‌کند.

## ۱) معماری

| لایه | فایل | نقش |
|---|---|---|
| داده | `wp-content/themes/sarzaminaryan-child/inc/county-profile.php` | کلیدهای کانونی متا + fallback به کلیدهای قدیمی `sa_cty_*`/`sa_city_*`، ثبت متا برای REST، باکس ویرایش «شناسنامهٔ شهرستان»، توابع همسایه/جاذبه/هم‌استانی و گزارش فیلدهای خالی |
| نمایش | `wp-content/themes/sarzaminaryan-child/template-parts/entity/county-profile.php` | کارت `sa-cyber-id--county` با خانه‌های `01 // EN_NAME` تا `11 // MAIN_CITY`، جدول جاذبه‌ها، ردیف شهرهای هم‌استانی و سه متن کوتاه زیر کارت |
| پیوند داده | `inc/relations.php`، `inc/geo-counties.php` | رابطهٔ `attraction.sa_city_id` و رجیستری ۴۸۳ شهرستانی (`data/counties.php`) |
| تست | `wp-content/themes/sarzaminaryan-child/tests/test-county-profile.php` | لایهٔ داده + قوانین خروجی کارت؛ در workflow ریلیز اجرا می‌شود |
| اسکیمای SEO | `inc/schema.php` | `AdministrativeArea` از همین داده‌ها غنی می‌شود (بدون JSON-LD دوم) |

## ۲) کلیدهای شناسنامه

هر کلید اول از نام کانونی خوانده می‌شود و اگر خالی بود از کلید قدیمی؛ خانهٔ خالی در خروجی
هیچ خانه/ردیفی نمی‌سازد.

| کلید کانونی | نوع | fallback قدیمی | در کارت |
|---|---|---|---|
| `county_en` | string | `sa_english_name` | `01 // EN_NAME` |
| `province_id` | integer | `sa_province_id` | `02 // PROVINCE` |
| `center_fa` | string | `sa_cty_center` | `03 // CENTER_CITY` |
| `center_en` | string | — | `03 // CENTER_CITY` |
| `main_city` | string | — | `11 // MAIN_CITY` |
| `main_city_en` | string | — | `11 // MAIN_CITY` |
| `population` | integer | `sa_cty_population` | `04 // POPULATION` |
| `population_year` | integer | `sa_cty_census_year` | `04 // POPULATION` |
| `area_km2` | number | `sa_cty_area` | `05 // ELEV_AREA` |
| `elevation_m` | integer | `sa_city_elevation` | `05 // ELEV_AREA` |
| `divisions_bakhsh` | integer | `sa_cty_districts` | `07 // DIVISIONS` |
| `divisions_shahr` | integer | `sa_cty_cities` | `07 // DIVISIONS` |
| `divisions_dehestan` | integer | `sa_cty_rural_districts` | `07 // DIVISIONS` |
| `divisions_rosta` | integer | `sa_cty_villages` | `07 // DIVISIONS` |
| `climate_short` | string | `sa_cty_climate` | `08 // CLIMATE_SEASON` |
| `best_season` | string | `sa_cty_best_time` | `08 // CLIMATE_SEASON` |
| `neighbors_n` / `neighbors_s` / `neighbors_e` / `neighbors_w` | string | `sa_cty_neighbors` (خط‌های جهت‌دار) | `10 // ACCESS_NEIGHBORS` |
| `language_main` | string | `sa_cty_language` | `09 // CULTURE_ECONOMY` |
| `economy_main` | string | `sa_cty_livelihood` | `09 // CULTURE_ECONOMY` |
| `distance_to_capital_km` | integer | `sa_cty_distance_center` | `10 // ACCESS_NEIGHBORS` |
| `lat` / `lng` | number | `sa_city_latitude` / `sa_city_longitude` | `06 // GEO_COORDS` + دکمهٔ نقشه |
| `history_now` | text | — | متن کوتاه زیر کارت: «قدمت و امروز» |
| `industry_main` | text | — | متن کوتاه زیر کارت: «مردم، صنعت و کارخانه‌ها» |
| `agriculture_main` | text | — | متن کوتاه زیر کارت: «کشاورزی و دامداری» |

سه کلید متنی زیر کارت کوتاه و مستند نوشته می‌شوند: `history_now` (قدمت و امروز)،
`industry_main` (شغل مردم، صنعت و کارخانه‌های مشهور با سال تأسیس، کارکرد و تولیدات) و
`agriculture_main` (کشاورزی و دامداری).

## ۳) قوانین خروجی (قطعی)

1. فیلد خالی = حذف کامل همان خانه/ردیف. هرگز «نامشخص»، «-» یا نشان فرایندی
   («نیازمند بازبینی») چاپ نمی‌شود.
2. جمعیت بدون سال سرشماری نمایش داده نمی‌شود (`population` و `population_year` با هم).
3. مختصات نامعتبر (غیرعددی یا بیرون بازهٔ ±۹۰/±۱۸۰) لینک نقشه نمی‌سازد.
4. همسایه و شهر هم‌استانی فقط وقتی لینک می‌شوند که صفحهٔ منتشرشده داشته باشند
   (`sa_county_permalink()` فقط `publish` را برمی‌گرداند)؛ در غیر این صورت فقط نام می‌آید.
5. مهم‌ترین شهر (`main_city`) هم فقط با صفحهٔ منتشرشده لینک می‌گیرد.
6. جدول جاذبه‌ها خودکار از رابطهٔ `attraction.sa_city_id` پر و لینک می‌شود و از راه
   شهرستان به استان وصل است؛ خطوط قدیمی POI فقط جای خالی را پر می‌کنند و لینک ندارند.
7. عددها فقط داخل شناسنامه می‌آیند و در بدنهٔ مقاله تکرار نمی‌شوند.
8. مرکز شهرستان هرگز از نام شهرستان حدس زده نمی‌شود و جمعیت «شهر» با جمعیت «شهرستان»
   جابه‌جا نمی‌شود (کلید مبهم `sa_city_population` عمداً در کارت خوانده نمی‌شود).

## ۴) منابع مجاز داده

- مرکز آمار ایران (سرشماری عمومی نفوس و مسکن؛ نتایج ۱۳۹۵ و به‌روزرسانی‌های رسمی بعدی).
- استانداری/فرمانداری همان شهرستان و تقسیمات کشوری رسمی (بخش، شهر، دهستان، روستا).
- ادارهٔ کل میراث فرهنگی، گردشگری و صنایع دستی استان (آثار ثبتی، جاذبه‌ها).
- سازمان هواشناسی (اقلیم، دما، بارش، بهترین فصل).
- کتاب یا پژوهش منتشرشده (سال تأسیس و تولیدات کارخانه‌ها، پیشینهٔ سکونت).

ویکی‌پدیا و متن فعلی صفحه فقط «سرنخ»‌اند، نه منبع؛ دادهٔ بی‌منبع معتبر اصلاً نوشته نمی‌شود
و خانه‌اش خالی می‌ماند. نام کارخانه فقط با نام دقیق، سال تأسیس و تولیدات قابل استناد می‌آید.

**در دسترس بودن منابع (راستی‌آزمایی ۱۴۰۵-۰۷-۲۵ / ۲۰۲۶-۱۰-۱۷):** وبگاه‌های رسمی
`amar.org.ir`، `irimo.ir`، `mcth.ir` و `*.khorasan.ir` از محیط اجرای Arena باز نمی‌شوند،
پس جمعیت، اقلیم، صنعت و کشاورزی را نمی‌توان مستقیم از خود منبع رسمی راستی‌آزمایی کرد.
منبع‌های در دسترسِ این نشست:

- فایل Drive مالک: «مرجع-مبنای-۱۴۰۴-استان-شهرستان-شهر.md» — دادهٔ رسمی تقسیمات کشوری تا
  پایان ۱۴۰۴ (`sajaddp/list-of-cities-in-Iran` نسخهٔ v3.1.2؛ ۳۱ استان، ۴۸۴ شهرستان،
  ۱۱۹۳ بخش، ۱۴۸۱ شهر، ۲۷۷۷ دهستان، ۹۹٬۳۱۷ آبادی) با مرکز هر شهرستان و مختصات GeoNames
  که خودِ سند آن را «تقریبی — نیازمند بررسی» می‌داند.
- `data/region-facts.php` قالب — مختصات «مرکز کادر محدودهٔ» هر شهرستان (خطا زیر ۰٫۲ درجه)،
  یعنی برای `lat`/`lng` دقیقِ مرکز شهرستان کافی نیست.
- `data/counties.php` — رجیستری ۴۸۳ شهرستانی قالب (نامک، نام فارسی، استان، وضعیت انتشار).

نتیجهٔ عملی: `center_fa`، `center_en`، شمار بخش/شهر/دهستان/روستا و `main_city` از سند
تقسیمات کشوری قابل استناد است؛ `population`/`population_year`، `area_km2`، `elevation_m`،
`climate_short`، `best_season`، `language_main`، `economy_main`، `distance_to_capital_km` و
سه متن `history_now`/`industry_main`/`agriculture_main` فقط وقتی نوشته می‌شوند که مالک منبع
معتبرشان (خروجی مرکز آمار، فرمانداری، میراث فرهنگی، هواشناسی یا کتاب/پژوهش) را در اختیار
بگذارد یا دسترسی شبکه به آن منبع فراهم شود.

## ۵) فازها

**فاز ۱ — زیرساخت و انتشار قالب.** لایهٔ متای کانونی، کارت ۱۱ خانه‌ای، قوانین خروجی،
تست‌ها و این سند؛ انتشار از راه PR به `main` و ریلیز خودکار ZIP (workflow
`release-child-theme.yml`). تنها شرط انتشار، تأیید صریح مالک است.

**فاز ۲ — سه نمونهٔ مرجع:** شهرستان کوهسرخ (خراسان رضوی)، دزپارت (خوزستان) و دورود
(لرستان). پرکردن کلیدهای بالا از راه WordPress REST API، نوشتن سه متن کوتاه زیر کارت،
پشتیبان‌گیری پیش از هر تغییر در `backup/{id}.json` (محلی؛ کامیت نمی‌شود) و گزارش فیلدهای
پر/خالی با ذکر منبع و لینک صفحه‌ها برای بازبینی مالک. بعد از گزارش، توقف تا تأیید.

**فاز ۳ — انتشار دسته‌ای (فقط با گفتن «ادامه» از سوی مالک).** استان‌به‌استان در دسته‌های
۲۰تایی؛ پیشرفت در `progress.json` (محلی)؛ نامک (slug) ثابت و بدون تغییر؛ `datePublished`
دست‌نخورده و `dateModified` برابر تاریخ واقعی همان دسته؛ جداکردن تصویر شاخص از نوشتهٔ
شهرستان بدون حذف فایل رسانه (فهرست در `reports/featured_images.csv`). بعد از هر دسته:
گزارش لینک‌ها، شهرستان‌های ردشده با دلیل، فیلدهای خالی شناسنامه و یادآوری به‌روزرسانی
sitemap Rank Math برای Search Console — و توقف کامل تا «ادامهٔ» بعدی.

## ۶) خط قرمزهای محتوایی

- هیچ جملهٔ فرایندی یا خطاب به ویراستار در خروجی عمومی.
- هیچ دادهٔ استانی به اسم شهرستان ثبت نمی‌شود.
- هیچ تناقضی بین شناسنامه، متن مقاله و FAQ.
- هیچ عدد یا نام ساختگی؛ هیچ جملهٔ قالبی تکراری در بیش از ۳ شهرستان.
- نام‌گذاری یکدست «شهرستان X» در عنوان، بردکرامب، اسکیمای SEO و لینک‌سازی داخلی.

## ۷) نوشتن روی سایت (REST)

- ابزار: `tools/county-sync/sync_county_meta.py` (+ `payload.template.json` و
  `tools/county-sync/README.md`). برای هر شهرستان پست را با نامک پیدا می‌کند، پشتیبان
  کامل را در `backup/{id}.json` می‌نویسد، کلیدها را POST می‌کند، سپس دوباره می‌خواند و
  گزارش می‌دهد (کلیدهای نشسته با منبعشان + کلیدهای خالی + ردشده‌ها با دلیل).
- قواعد اجبارشده در خود اسکریپت: کلید بی‌منبع نوشته نمی‌شود؛ کلید ناشناخته خطاست
  (فهرست کلیدها مستقیم از `sa_county_profile_fields()` خوانده می‌شود)؛ `population` فقط با
  `population_year`؛ `lat`/`lng` فقط با هم و در بازهٔ معتبر؛ نامک و `date` هرگز فرستاده
  نمی‌شوند و `date_modified` فقط با پرچم صریح `--modified-date` (برای دسته‌های فاز ۳).
- فایل‌های دادهٔ دسته‌ها، پشتیبان‌ها و `progress.json` کامیت نمی‌شوند (محل پیشنهادی
  `tools/importers/county-identity/<batch>.json`).
- اعتبارنامه: `SA_SITE_URL`، `SA_USER` و `SA_APP_PASSWORD` در `.env` محلی
  (هرگز در چت یا مخزن چاپ/کامیت نمی‌شود؛ `.env` در `.gitignore` است).
- مانع فنی شناخته‌شده: `inc/security.php` فعلاً
  `add_filter( 'wp_is_application_passwords_available', '__return_false' )` را دارد، پس
  نوشتن با Application Password تا برداشتن موقت آن فیلتر (یا استفاده از WP-CLI/پیشخوان)
  ممکن نیست. این تغییر باید آگاهانه و با تأیید مالک انجام شود.
- پیش از هر نوشتن: پشتیبان کامل محتوا/متا/تصویر همان پست در `backup/{id}.json`.
