## LEVEL 3 — RELATION RULES

```
Province
    -> Cities
    -> Attractions
    -> Foods
    -> Souvenirs
    -> Routes
    -> Accommodations          [reserved]

City
    -> Province
    -> Attractions
    -> Foods
    -> Souvenirs
    -> Routes
    -> Accommodations          [reserved]

Attraction
    -> City
    -> Province
    -> Nearby Accommodations   [reserved]

Food
    -> City
    -> Province

Souvenir
    -> City
    -> Province

Route
    -> Cities
    -> Attractions
    -> Accommodations          [reserved, optional]

Accommodation                  [reserved]
    -> City
    -> Province
    -> Nearby Attractions
```

**Integrity rules**

1. Every `belongs_to -> City` implies `belongs_to -> Province` of that city. The two must never disagree.
2. `related_many`, `near_many` and `belongs_to_many` are stored as explicit edges (no free-text lists).
3. `near_many` edges carry `distance_km`.
4. Deleting a City is blocked while any Attraction / Food / Souvenir / Accommodation points to it.

## LEVEL 5 — SEO FIELDS AND GENERATED OUTPUT

For active entities, these author-entered SEO inputs are required by the current publish gate:

| Field | Purpose / contract |
|---|---|
| `seo_title` | Accurate, distinctive page-title text; required on publish. The theme has a generated fallback if a post bypasses the gate. |
| `seo_description` | Accurate, unique summary; required on publish. The theme can generate a fallback, and Google may use page text instead. |
| `focus_keyword` | Internal editorial brief for the primary search intent; required as a brief, **not** a Google ranking field and not a reason to repeat a phrase unnaturally. |

Visible FAQ content (`faq_content`) is **optional** and belongs on the reader-facing page only when it answers a genuine user question. Do not manufacture Q&A or treat FAQ as a publish/structured-data requirement.

These are generated from the rendered page or may have optional overrides; they are not mandatory author-entered fields on every post:

| Output | Default |
|---|---|
| `og_title`, `og_description` | Derived from the document title and description; optional override when needed. |
| `breadcrumb_schema` | Generated from the visible breadcrumb trail where one exists. |
| `canonical_url` | Generated from the permalink; override only for a documented canonical/migration case. |

**Deprecated:** `faq_schema` is a legacy field name. Visible FAQ content remains supported, but the theme must not emit a Google `FAQPage` rich-result node. Google stopped showing FAQ rich results on 2026-05-07; FAQ quantity is not a ranking target. Schema.org output must match visible page facts and does not guarantee a rich result.

Additional for Accommodation 🟡: `booking_url` must be output with `rel="sponsored nofollow"`; `is_sponsored = true` requires a visible disclosure block.

## LEVEL 7 — CONTENT QUALITY AND PUBLISH GATE

Every entity should have a clear introduction, relevant key facts where applicable, contextual internal links, and correct page-level SEO metadata. A visible FAQ is added only when it answers real questions; it is not a mandatory count or structured-data target.

**Hard blockers in the current publish gate:**

- Missing required parent relation
- Missing editable SEO title/description/primary query
- Missing required featured image (except the attraction design that has its own image/card behavior)
- Missing primary taxonomy
- Missing sources where that entity type has a non-zero source minimum
- Duplicate body H1, unresolved editorial placeholder, or an empty/unlabelled link

**Advisories (not publication locks or ranking quotas):** FAQ count, contextual internal-link count, coordinates where they depend on external data, source freshness/coverage where applicable, and stale verification dates.

**Additional publish blockers for Accommodation** 🟡

- Missing `belongs_to -> City`
- Missing `accommodation_type`
- `is_sponsored = true` without disclosure block
- `booking_url` present without `affiliate_provider`

---

**v1.2 thresholds** live in `schema/data-model.yaml → content_rules.minimums`. FAQ and internal-link counts are editorial diagnostics; do not add filler to reach them. Current advisory targets are 3 visible Q&A when useful; province 5/city 5/attraction 3/route 3/food 2/souvenir 2 contextual links. Source-line minimums remain 5 for Province and City, 2 for Route/Food/Souvenir/Accommodation, and 0 for Attraction (the count does not waive fact-checking of claims). Coordinates remain required in the data model where available, but the runtime gate treats missing coordinates as an advisory.

- `missing_content_hygiene` blocks body H1 duplication, unresolved editorial notes/placeholders, and empty/unlabelled anchors.
- `[نیازمند بررسی]` / `[منبع لازم]` remain explicit transparency markers rendered visibly; use sparingly and resolve before routine publication whenever a reliable source exists.
- `attraction.last_verified_date` older than 365 days ⇒ «needs review» badge (does not block).
- Production prompts per entity: `content-templates/province.md`, `city.md`, `attraction.md`.

## APPENDIX A — Accommodation activation plan

Activation must not change anything in Levels 1–6 for the six active entities beyond filling the reserved slots already listed above.

| Step | Action |
|---|---|
| 1 | Register CPT `accommodation` and taxonomy `accommodation_type`. |
| 2 | Add the reserved relation fields on Province / City / Attraction / TravelRoute (`has_many` / `near_many` → Accommodation). |
| 3 | Enable URL `/accommodation/{accommodation-slug}` and the hub page `/city/{city-slug}/where-to-stay`. |
| 4 | Add "Where to stay" blocks to the City and Attraction templates (Level 6 links). |
| 5 | Apply Level 5 SEO fields + Level 7 rules, including the sponsored-link rules. |
| 6 | Bump this model to the next appropriate version, record it in `CHANGELOG.md`, regenerate `schema/`, and verify the child-config generator does not drop active fields. |

**Rationale (as delivered, Persian):**

> برای آینده، یک موجودیت هفتم هم از ابتدا در دیتامدل پیش‌بینی کن، حتی اگر فعلاً نسازی: چون بعداً اگر بخواهی از همکاری در فروش، رزرو هتل، تبلیغات اقامتگاه یا صفحات «کجا اقامت کنیم؟» درآمد بگیری، مجبور نمی‌شوی کل معماری سایت را دوباره بازطراحی کنی. این یکی از رایج‌ترین اشتباهات سایت‌های گردشگری فارسی است که فقط روی شهر و جاذبه تمرکز می‌کنند و بخش اقامت را ساختاریافته طراحی نمی‌کنند.
