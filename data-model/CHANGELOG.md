# Changelog — Master Data Model

All notable changes to the data model are recorded here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) · Versioning: `MAJOR.MINOR` (MAJOR = breaking change to an active entity/URL, MINOR = additive).

## [1.2] — 2026-10-07

### Changed
- Clarified the public meaning of the legacy CPT `city`: it represents the site’s county destination pages (the 483-county registry), not necessarily a municipality. Existing CPT name, keys, URLs, and `/city/{slug}` routes remain locked; any rename requires a migration and redirect plan.
- Reframed Level 5 as required editorial inputs versus generated/optional overrides. `seo_title`, `seo_description`, and `focus_keyword` remain model-required; OG title/description, breadcrumb schema, and canonical are generated by default and may be overridden only when justified. `focus_keyword` is an internal brief, not a Google ranking field.
- Deprecated `faq_schema`; FAQ remains optional, visible reader content. The child theme no longer emits `FAQPage` JSON-LD. Google stopped showing FAQ rich results in Search on 2026-05-07; FAQ count is not a ranking quota.
- Reclassified FAQ count, internal-link count, and missing coordinates as editorial advisories. Per-entity values are diagnostics only; no filler should be added to reach them. Non-zero source minimums remain publish blockers; Attraction’s source-count minimum stays zero, without exempting factual claims from verification.

### Added
- Documented seven already-active Attraction fields in the machine-readable model: `english_name`, `attraction_age`, `attraction_area`, `elevation`, `access_level`, `trail_note`, and `safety_note`.
- Added a machine-readable county profile extension for the existing fixed `sa_cty_*` fields and documented the separate registry/runtime. The model explicitly records that `sa_city_population` and `sa_cty_population` coexist; neither is to be inferred from or copied over the other without an authoritative source and an approved migration.
- Added `missing_content_hygiene` as a hard publish blocker for body H1s, unresolved editorial placeholders, and empty/unlabelled links. The visible transparency markers `[نیازمند بررسی]` and `[منبع لازم]` are allowed and are not placeholders.
- Aligned runtime generation and publish checks with v1.2: preserve active Attraction fields/labels; emit required, optional, deprecated, advisory, and hygiene metadata separately; enforce content-hygiene blockers; keep FAQ/link/coordinate diagnostics out of the blocking set; and represent county pages as `AdministrativeArea` rather than `City` in the theme’s entity graph.
- Added a county-name normalizer for attraction cards and the attraction identity block, so a stored leading «شهرستان» does not become «شهرستان شهرستان» when the UI supplies the label; no post title or URL is bulk-migrated.

### Notes
- No active CPT, field key, taxonomy slug, relation key, or URL was renamed. Accommodation remains reserved.
- Theme release/version metadata is intentionally not bumped in this change set while PR #8 owns the current release files; integrate the runtime changes with the post-PR-#8 release plan before publishing a theme release.
- The following proposed fields are **deferred**, not approved or implemented: `attraction.national_registration_number`, `attraction.national_registration_date`, `attraction.unesco_year`, `attraction.unesco_url`, `attraction.area_m2`, `attraction.elevation_m`, and `last_verified_date` for all entities. Add only after an authoritative data source and owner approval are available.

## [1.1] — 2026-09-26

### Added
- **Attraction** fields `official_website` (url, nullable → JSON-LD `sameAs`) and `last_verified_date` (date, nullable; staleness > `stale_after_days` = 365 flags «needs review»). Requested so outdated hours / prices / access restrictions can be identified.
- **Level 7** — `content_rules.minimums` per entity (FAQ, sources, internal links, coordinates), three new publish diagnostics (`missing_coordinates`, `missing_sources`, `missing_internal_links`), `uncertainty_markers` (`[نیازمند بررسی]`, `[منبع لازم]` — allowed, badged, counted) and `stale_after_days`.
- Production prompts: `content-templates/province.md`, `city.md`, `attraction.md` (owner packages #1–#3).

### Notes
- Additive only (MINOR bump). No slug/URL/relation change. The child theme generator reads YAML (`schema/build_child_config.py`).

## [1.0] — 2026-09-26

### Added
- **Level 1** — six active core entities: `Province`, `City`, `Attraction`, `TravelRoute`, `LocalFood`, `Souvenir` (CPT, primary key, fields, relations).
- **Level 1** — reserved seventh entity **`Accommodation`** (`hotel`, `eco_lodge`, `guest_house`, `traditional_house`, `camping`) with locked field names, `belongs_to -> City`, `near_many -> Attraction`, and reserved inverse relation slots on Province / City / Attraction / TravelRoute. Not built in v1.0.
- **Level 2** — taxonomies `province_tax`, `attraction_type`, `travel_season`, `travel_budget`, `travel_duration`; reserved `accommodation_type`; primary taxonomy defined per entity.
- **Level 3** — relation rules + integrity rules R1–R4.
- **Level 4** — URL structure for all entities; reserved `/accommodation/{slug}` and hub page `/city/{slug}/where-to-stay`; slug rules.
- **Level 5** — SEO fields for entities; reserved sponsored-link rules for Accommodation.
- **Level 6** — internal link graph, including reserved accommodation links.
- **Level 7** — AI content rules and publish gate; reserved extra blockers for Accommodation.
- `schema/data-model.yaml` + generated `schema/data-model.json` + `schema/build_json.py`.
- `raw/master-data-model-v1.0.original.txt` — original delivered text preserved verbatim.
