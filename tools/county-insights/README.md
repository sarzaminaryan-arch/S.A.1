# ابزار «از تجربهٔ مسافرها» — دادهٔ زندهٔ شهرستان‌ها (CU-1/CU-2)

هدف: تبدیل تجربه‌های تازهٔ مردم (نظرات گوگل‌مپ، نشان، بلد، صفحه‌های اقامتگاه‌ها و سفرنامه‌ها)
به بلوک دادهٔ ساخت‌یافته‌ای که روی صفحهٔ شهرستان می‌نشیند و متن ثابت مقاله را زنده می‌کند
(بلوک «از تجربهٔ مسافرها»، قالب 2.22.49). خلاصهٔ راهبرد در
`docs/live-site/core-update-2026-plan.md` است.

## گردش‌کار هر شهرستان

1. **جمع‌آوری:** برای شهرستان، نظرات تازه و پُرجزئیات را از گوگل‌مپ (فیلتر Newest/Lowest)،
   نشان/بلد و نظرات اقامتگاه‌ها کپی کنید (۱۵ تا ۲۵ نظر کافی است). نام و تاریخ کاربران لازم نیست.
2. **استخراج:** متن خام + نام شهرستان را به پرامپت `extract_prompt.md` بدهید؛ خروجی فقط JSON است.
   قانون‌ها: دادهٔ ناموجود `null` (حدس ممنوع)، حواشی احساسی حذف، هر نکته حداکثر ~۳۵ کلمه،
   لحن رسمی و کاربردی. «ویژگی مردم» فقط شهرت مثبت و از زبان تجربهٔ مسافرها.
3. **ثبت:** JSON را در `data/raw/<slug>.json` بگذارید (مثل `data/raw/tehran.json`) و اجرا کنید:

   ```bash
   python3 tools/county-insights/county_insights.py build
   ```

   خروجی: `data/counties-insights.json` (ادغام همهٔ شهرستان‌ها)، برای هر شهرستان
   `out/<slug>.meta.json` (کلیدهای کانونی آمادهٔ ورود به شناسنامه) و
   `out/<slug>.preview.md` (پیش‌نمایش خوانا برای بازبینی مالک).
4. **بازبینی انسانی (اجباری):** پیش‌نمایش را بخوانید؛ هر عدد/ادعای مشکوک را حذف یا اصلاح کنید.
   وضعیت `draft_needs_review` یعنی هنوز راستی‌آزمایی نشده. متن نظرات مردم عیناً کپی نمی‌شود؛
   بازنویسیِ ماست و انتشار نهایی فقط با تأیید مالک (دروازهٔ انتشار قالب).
5. **ورود به سایت:** مقادیر `out/<slug>.meta.json` در متاباکس «شناسنامهٔ شهرستان» همان
   شهرستان وارد می‌شود؛ فیلد خالی روی سایت چیزی نشان نمی‌دهد. `field_update_note` را با
   فصل/سال و شرح کوتاه تغییر پر کنید تا تازگی برای خواننده و گوگل روشن باشد.
6. **به‌روزرسانی:** هر ~۶ ماه نظرات تازه را دوباره از مرحلهٔ ۱ بروید و فایل خام را جایگزین کنید.

## اولویت شهرستان‌ها

تهران (انجام شد، پیش‌نویس) ← اصفهان ← تبریز ← شیراز ← مشهد ← بقیهٔ پربازدیدها.
هر شهرستان یک فایل و یک بازبینی جدا دارد؛ عجله‌ای در کار نیست، خالی‌ماندن فیلدها بی‌هزینه است.
