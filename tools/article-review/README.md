# خروجی فقط‌خواندنی برای بازبینی مقالات — فازهای ۳ و ۵

این ابزار **ویرایشگر، پاک‌کننده، backup کامل یا ابزار نصب قالب نیست**. متن‌های واقعی سایت در مخزن موجود نیستند؛ ۱۰۵ مقالهٔ همراه قالب و fixtureهای `9001–9003` جایگزین ۴۸۰ مقالهٔ سایت نیستند. هیچ fallback ساختگی وجود ندارد.

## اجرا روی هاست واقعی توسط مدیر سایت

پیش‌نیاز: WP-CLI، PHP 7.4+، مسیر واقعی وردپرس و کاربر مدیر. این دستور در محیط فعلی اجرا نشده است. فایل PHP را از همین برنچ دریافت کنید؛ نیازی به نصب قالب جدید نیست.

```bash
# دایرکتوری خصوصی باید بیرون تمام مسیرهای قابل دسترسی از وب باشد، نه فقط بیرون wp-content.
mkdir -m 700 /PRIVATE_PATH/sa-review
wp --path=/WORDPRESS_PATH --user=ADMIN_LOGIN eval-file /TOOLS_PATH/export.php -- --output=/PRIVATE_PATH/sa-review/articles.jsonl --expected=480
```

مسیرها و نام کاربری را روی هاست خودتان جایگزین کنید؛ رمز، توکن یا فایل تنظیمات وردپرس لازم نیست ارسال شود. ابزار دسترسی مدیر را بررسی می‌کند، خروجی زیر مسیر وردپرس را رد می‌کند، فایل تازه را با دسترسی `0600` می‌سازد و فایل قبلی را بازنویسی نمی‌کند. انتخاب مسیر واقعاً خارج از web root با مدیر میزبان است. برای اجرای مجدد نام فایل تازه بدهید.

- قلمرو: رکوردهای `publish` در انواع ثبت‌شدهٔ `post`، `city`، `province`، `attraction`، `travel_route`، `local_food`، `souvenir`؛ بدون revision، page، attachment یا پیش‌نویس. قلمرو و تعداد واقعی در خروجی درج می‌شود. اگر مجموعهٔ ۴۸۰تایی متفاوت است باید با شناسه‌های واقعی تطبیق داده شود؛ شمارش به‌تنهایی اثبات پوشش نیست.
- خروجی JSONL: یک header، هر مقاله در یک خط و یک summary نهایی با `complete=true`. فایل بدون این footer کامل نیست. اختلاف با ۴۸۰ هشدار می‌گیرد؛ هیچ رکوردی برای رسیدن به این عدد ساخته یا حذف نمی‌شود.
- هر مقاله: شناسه/نامک/عنوان/نوع/URL/زمان تغییر، بدنهٔ خام و SHA-256 آن، چکیده، `sa_sources` خام و متای کانونی/قدیمی شناسنامهٔ شهرستان؛ برای فاز ۵، `faq_raw` عین مقدار `sa_faq` و `facts_checked` عین `sa_facts_checked` نیز صادر می‌شوند. FAQ خالی/JSON خراب/ردیف ناقص اصلاح یا حذف نمی‌شود؛ باید در بازبینی دیده شود. تاریخ خالی جعل نمی‌شود و داشتن تاریخ هم اثبات صحت ادعا نیست. این دو فیلد به schema فعلی افزوده شده‌اند؛ خروجی‌های قدیمی ممکن است آن‌ها را نداشته باشند و باید دوباره گرفته شوند.
- پوشش شناسنامه **ناقص و صریح** است: فقط شهرستان و فقط کلیدهای معرفی‌شده توسط `sa_county_profile_fields()` قالب فعال. نبود تابع یا نوع دیگر با `identity_coverage=unavailable` مشخص می‌شود. داده‌های جایگزینِ رجیستری، مقادیر محاسباتی و HTML نهایی کارت صادر نمی‌شوند؛ برای تشخیص تمام تکرارها باید شناسنامهٔ واقعاً نمایش‌داده‌شده هم بازبینی شود.
- `theme_version` فقط در صورت وجود ثابت قالب ثبت می‌شود؛ با گزارش نصب کاربر یکی فرض نمی‌شود. `provenance=wordpress_export` اجرای اسکریپت روی WordPress را نشان می‌دهد، نه اثبات خودکار اینکه همان سایت production است.
- اسکریپت هیچ دستور نوشتن دیتابیس ندارد؛ `database_writes=0` دربارهٔ خود این صادرکننده است، نه تضمین رفتار تمام hookها/افزونه‌های هنگام بارگذاری وردپرس. از `the_content` یا رندر shortcode استفاده نمی‌شود.
- خواندن صفحه‌ای snapshot تراکنشی نیست (`consistent_database_snapshot=false`). هنگام خروجی‌گیری مقالات و متای آن‌ها ویرایش نشوند؛ فایل با شناسه‌ها/زمان‌های تغییر سایت تطبیق داده شود. تغییر statusِ رکورد خوانده‌شده باعث توقف و نبود footer کامل می‌شود؛ همهٔ ویرایش‌های هم‌زمان قابل تشخیص نیستند.
- فایل شامل متن خام است و ممکن است متن مقالهٔ رمزدارِ منتشرشده نیز داشته باشد؛ آن را عمومی یا داخل Git قرار ندهید. پس از انتقال امن، نسخهٔ موقت را طبق سیاست میزبان پاک کنید.

## گام بعدیِ محتوایی (هنوز انجام نشده)

فایل واقعی و کامل `articles.jsonl` را به همین گفتگو پیوست کنید؛ اطلاعات ورود نفرستید. سپس برای هر مقاله، متن اصلی و متن پیشنهادی با hash پیش از ویرایش، منابع، وضعیت چهار بخش و وضعیت شناسنامه ثبت می‌شود:

1. **معرفی شهر:** بازنویسی روان و بدون عدد/آمار یا تکرار شناسنامه؛ نه حذف صرف رقم‌ها و باقی گذاشتن جملهٔ ناقص. عددهای حروفی هم نیازمند بررسی‌اند.
2. **پیشینه تغییر نام:** تغییر عنوان «وجه تسمیه» فقط همراه بررسی محتوای واقعی تغییر نام؛ اگر اطلاعات قابل اتکایی نیست کل بخش حذف می‌شود. ریشه‌شناسی حدسی معادل تاریخ تغییر نام نیست.
3. **مردم و زبان:** فقط مردم/فرهنگ/زبان/گویش، بدون آمار جمعیت.
4. **اقتصاد:** فقط اطلاعات موجود و قابل اتکای فعالیت شاخص، بدون عدد؛ در نبود اطلاعات کل بخش حذف می‌شود.

وجود یک ادعا در متن یا متا، صحت آن را ثابت نمی‌کند؛ مطلب نامطمئن علامت می‌خورد و واقعیت تازه ساخته نمی‌شود. پیش از هر اعمال انبوه: پشتیبان معتبر + dry-run + گزارش تفاوت‌ها؛ شناسنامه، پنج حذف فاز ۲ و سایر بخش‌ها نباید تغییر کنند. این پوشه **هیچ دستور apply/import ندارد**.

## فاز ۵ — کنترل انسانی، نه فیلتر حدسی

- «حقایق جالب» از متن کامل مقاله خوانده می‌شود؛ کلید متای تازه‌ای برای آن اختراع نشده است. هر واقعیت باید شاهد مشخص داشته باشد. روایت مثبت فرهنگی فقط با شاهدِ وجود همان روایت و عبارت «گفته می‌شود» یا «بنا بر روایت» قابل استفاده است؛ عبارت احتیاط جای منبع را نمی‌گیرد. شایعه/توهین/ادعای آسیب‌زا در این بخش وارد نمی‌شود.
- FAQ باید **۳ تا ۵ پرسش اختصاصی همان شهر**، متمایز از یکدیگر و از سایر بخش‌ها داشته باشد. پاسخ پیشنهادی یک یا دو جملهٔ کوتاه است. تکرار معنایی هم بررسی می‌شود؛ عوض کردن جمله‌بندی کافی نیست.
- سؤال/پاسخ با بدنهٔ کامل، FAQ داخل بدنه و `faq_raw` و شناسنامهٔ واقعاً نمایش‌داده‌شده تطبیق داده می‌شود. اعداد فارسی/عربی/لاتین و عددهای حروفی هم بررسی می‌شوند تا آمار شناسنامه در پاسخ تکرار نشود؛ حذف کور همهٔ رقم‌ها مجاز نیست.
- اگر برای پرسش‌های کافی یا روایت معتبر داده نیست، کمبود گزارش می‌شود؛ FAQ عمومیِ کپی‌شده، پرکردن تا حداقل تعداد، حذف خودکار سؤال‌های ششم به بعد یا تبدیل ادعای نامطمئن به «گفته می‌شود» انجام نمی‌شود.
- این‌ها معیارهای بازبینی‌اند، نه تغییر publish gate و نه ادعای انجام ویرایش. منبعِ هر تغییر و تفاوت قبل/بعد ثبت می‌شود؛ پیش از اعمال انبوه backup و dry-run لازم است. FAQPage JSON-LD طبق رفتار فعلی قالب خاموش می‌ماند.

## تست آفلاین

فقط دادهٔ ساختگی `fixture.invalid` و ۵۱ رکورد برای آزمون صفحه‌بندی؛ هیچ اتصال سایت انجام نمی‌شود:

```bash
php -l tools/article-review/export.php
php -l tools/article-review/test-export.php
for mode in normal mismatch not-cli denied inside-root bad-count unknown-option overwrite changed-status empty-faq malformed-faq array-faq; do
  php tools/article-review/test-export.php "$mode" || exit 1
done
```

انتظار: ۱۲ خط `PASS`؛ تست‌ها حفظ FAQ خامِ سالم/خالی/خراب/غیررشته‌ای و تاریخ خالی، متن/hash، منابع، متای کانونی/قدیمی، اختلاف تعداد، مجوز فایل، خطای دسترسی، جلوگیری از overwrite و خروجی نیمه‌تمام را می‌سنجند. هر فراخوانی نوشتن متداول WordPress در mock تست خطا می‌دهد. بررسی محتوایی ۴۸۰ مقاله یا صحت عملکرد تمام افزونه‌های سایت از این تست‌ها نتیجه نمی‌شود.
