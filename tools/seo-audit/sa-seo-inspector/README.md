# SA SEO Inspector — افزونهٔ تشخیصی یک‌بارمصرف

خروجی این پوشه یک افزونهٔ **فقط‌خواندنی** است که وضعیت *واقعی* سایت زنده (`sarzaminaryan.ir`)
را استخراج می‌کند تا با داده‌های Search Console و رجیستری قالب مقایسه شود.
هیچ نوشته‌ای را تغییر نمی‌دهد، هیچ آپشنی را نمی‌نویسد، کش را پاک نمی‌کند و ایمیل نمی‌فرستد؛
تنها کاری که می‌کند چند درخواست HTTP به خودِ سایت است (مثل کاری که گوگل‌بات انجام می‌دهد).

## ساخت فایل نصب

```bash
python3 tools/seo-audit/build_inspector_zip.py
# → .tmp/dist/sa-seo-inspector-1.0.0.zip
```

فایل `.zip` عمداً در گیت نگه داشته نمی‌شود (`.tmp/` در `.gitignore` است)؛ هر بار با همین اسکریپت ساخته می‌شود.

## نصب (یک بار)

1. پیشخوان وردپرس ← **افزونه‌ها ← افزودن ← بارگذاری افزونه** ← فایل zip را انتخاب و نصب کنید.
2. فعال‌سازی کنید.
3. به **ابزارها ← SA SEO Inspector** بروید.
4. دکمهٔ **«دانلود گزارش JSON»** را بزنید (پیمایش کامل ۱۶۰+ URL بین ۲ تا ۵ دقیقه طول می‌کشد؛ صفحه را نبندید).
5. فایل `sa-seo-inspector-YYYYMMDD-HHMMSS.json` دانلود می‌شود ← آن را در پوشهٔ «سایتمپ» در گوگل‌درایو بگذارید
   (یا مستقیم برای تحلیل برگردانید).
6. **افزونه را غیرفعال و حذف کنید.**

اگر می‌خواهید سریع‌تر باشد، تیک «بدون پیمایش URLها» را بزنید؛ در این حالت فقط موجودی/تنظیمات
بدون بخش `probes` خروجی می‌شود.

## چه چیزی جمع‌آوری می‌شود

| کلید JSON | محتوا | کدام پرسش را جواب می‌دهد |
|---|---|---|
| `environment` | نسخهٔ WP/PHP/قالب، `permalink_structure`، `blog_public`، افزونه‌های فعال، CPT/تکسونومی‌های ثبت‌شده **با اسلگ rewrite**، قواعد rewrite مرتبط | آیا `/province/` واقعاً بیس CPT است؟ الگوی `/provinces/` از کدام قاعده می‌آید؟ |
| `seo_plugins` | نسخهٔ Rank Math (+Pro)، همهٔ آپشن‌های `rank_math_*` (بدون کلید/توکن/لایسنس)، وضعیت کناررفتن سئوی قالب | مالک واقعی sitemap و robots کیست؟ |
| `robots_files` | متن `robots.txt` سروشده + **فایل‌های فیزیکی ریشه** (`robots.txt`, `sitemap.xml`, `sitemap_index.xml`, `wp-sitemap.xml`, هر `*.xml` ریشه) + `.htaccess` | منبع الگوهای wildcard `/*`, `/wp-*.php`, `/wp-content/uploads/*` کجاست؟ |
| `sitemaps` | هر سه منبع سایت‌مپ با وضعیت HTTP، ریدایرکت و **فهرست کامل همهٔ URLهای داخلشان** | سایت‌مپ جدید چه چیزی می‌فرستد؟ |
| `probes` | برای هر URL: کد وضعیت، `Location`، `X-Robots-Tag`، و در 200: عنوان، `meta robots`، `canonical`، تعداد H1، انواع JSON-LD، شمار واژه | کدام URL واقعاً 301/noindex/duplicate است (نه حدس) |
| `inventory` | شمارش پست بر پایهٔ نوع/وضعیت، همهٔ برگه‌ها (با ID)، همهٔ استان‌ها و جاذبه‌ها، **همهٔ شهرستان‌ها با طول محتوا و متاهای noindex/canonical**، اسلاگ‌های عددی، اسلاگ‌های تکراری، ترم‌های همهٔ تکسونومی‌ها با شمارش واقعی | چند شهر واقعاً منتشر است؟ کدام جفت‌ها تکراری‌اند؟ ترم `family` وجود دارد؟ |
| `content_scan` | جست‌وجوی الگو در محتوای منتشر: `W_*`، `/editorial-policy`، `/ostan/`، `/provinces/`، `-city/`، `-county/`، `page_id=`، صفحه‌بندی `/season/…/page/…`، اسلاگ‌های عددی جاذبه — به‌تفکیک پست + نمونهٔ متن؛ به‌علاوهٔ **همهٔ آیتم‌های منوها** و ویجت‌های متنی | لینک‌های خراب از کدام پست/منو تولید می‌شوند؟ |
| `redirections` | نقشهٔ ۳۰۱ قالب (`data/redirects.php`)، جدول `wp_rank_math_redirections`، افزونه‌های ریدایرکت | منبع 301 روی `/provinces/ardabil/` چیست؟ نقشهٔ قالب روی سایت فعال است یا نه؟ |

## نکات ایمنی

- فقط مدیر کل (`manage_options`) با nonce می‌تواند گزارش بگیرد.
- آپشن‌هایی که نامشان شامل `license/token/secret/password/auth/key/private/salt/cred` است **هرگز** خروجی نمی‌شوند.
- رشته‌های بلند بریده می‌شوند تا JSON کوچک بماند.
- `.htaccess` و محتوای فایل‌های ریشه در گزارش هست (برای یافتن منبع wildcard لازم است)؛ فایل را فقط
  در درایو خصوصی خودتان نگه دارید.
- افزونه هیچ قلاب دائمی روی سایت نمی‌گذارد؛ با حذف آن هیچ چیزی باقی نمی‌ماند.

## بعد از گرفتن گزارش

گزارش را با `tools/seo-audit/analyze_gsc.py` (دادهٔ GSC) و رجیستری قالب مقایسه می‌کنیم و برای هر
URL یک اقدام قطعی (۳۰۱ / noindex / تغییر اسلاگ / حذف از سایت‌مپ / انتشار) تعیین می‌شود.
