# پل ایجنت وردپرس (`tools/wp-agent`)

راه مستقیم ایجنت برای خواندن و نوشتن در وردپرس سایت، از قالب **2.22.72** به بعد.
سمت سایت در `wp-content/themes/sarzaminaryan-child/inc/agent-bridge.php` و با فضای نام `/wp-json/sa-agent/v1` کار می‌کند.

## قواعد مالک (هم سمت سایت اجرا می‌شوند، هم در اسکریپت)

| کار | قاعده |
|---|---|
| خواندن | آزاد است: نوشته‌ها، برگه‌ها، استان، شهرستان، دیدنی و مسیر (حتی پیش‌نویس‌ها)، همراه متا و برچسب‌ها. |
| مقالهٔ تازه | **فقط پیش‌نویس.** هر وضعیتی هم فرستاده شود، `draft` ذخیره می‌شود. فرمان انتشار وجود ندارد. |
| تغییر نوشتهٔ موجود | **اول پشتیبان، بعد تغییر.** پشتیبان در دو جا گرفته می‌شود: روی سایت (ابزارها ← «پشتیبان‌های ایجنت»، فقط مدیر می‌بیند) و در runner (artifact خصوصی، ۹۰ روز). اگر پشتیبان ساخته نشود، چیزی نوشته نمی‌شود. |
| متن مقالهٔ منتشرشده | مستقیم عوض نمی‌شود. یک **پیش‌نویس بازنویسی** (`draft-copy`) کنارش ساخته می‌شود و مالک خودش منتشرش می‌کند. فقط با دستور صریح مالک: `update --owner-approved-live-edit`. |
| ظاهر (سفارشی‌ساز) | اول پشتیبان کامل از همهٔ `theme_mods`، بعد تغییر. فقط کلیدهای `sa_*` یا کلیدهای موجود، و فقط مقدار ساده. |
| ساختار (کد قالب) | فقط از راه نسخهٔ تازهٔ قالب و Release. نسخهٔ قبلی همیشه روی GitHub می‌ماند و همان پشتیبان است. |
| حذف | **هیچ مسیر حذفی وجود ندارد.** نامک، وضعیت و تاریخ انتشار هم با این پل عوض نمی‌شوند. |
| متن | واژه‌های ممنوع (`راستش`، اصطلاحات هوش مصنوعی و «بازبینی انسانی») رد می‌شوند. ایجنت برچسب یا دستهٔ تازه نمی‌سازد. |
| هم‌زمانی | هر به‌روزرسانی `modified_gmt` خوانده‌شده را می‌فرستد. اگر کسی در این فاصله نوشته را عوض کرده باشد، نوشتن با 409 رد می‌شود. |
| بازگردانی | `restore <backup_id>`. پیش از بازگردانی هم از وضع فعلی پشتیبان گرفته می‌شود. |

## کار یک‌بارهٔ مالک (حدود ۵ دقیقه)

1. **نصب قالب 2.22.72**: پیشخوان ← نمایش ← پوسته‌ها (یا به‌روزرسان GitHub داخل قالب).
2. **ساخت کاربر مخصوص ایجنت (پیشنهادی)**: کاربران ← افزودن ← نام کاربری مثلاً `sa-agent`.
   - نقش **ویرایشگر** برای خواندن و پیش‌نویس کافی است.
   - اگر می‌خواهید ایجنت تنظیمات ظاهر (سفارشی‌ساز) را هم با پشتیبان عوض کند، نقش **مدیر کل** لازم است.
3. **ساخت Application Password**: کاربران ← همان کاربر ← ویرایش ← پایین صفحه، بخش «رمزهای عبور برنامه» (Application Passwords).
   - نام را `sa-agent-github` بگذارید و «افزودن رمز عبور برنامهٔ جدید» را بزنید.
   - رمز ۲۴ حرفی **فقط یک بار** نمایش داده می‌شود؛ کپی‌اش کنید.
4. **گذاشتن رمز در GitHub (نه در چت)**: مخزن ← Settings ← Secrets and variables ← Actions ← New repository secret. این سه را بسازید:

   | Name | Value |
   |---|---|
   | `SA_SITE_URL` | `https://sarzaminaryan.ir` |
   | `SA_USER` | نام کاربری مرحلهٔ ۲ (مثلاً `sa-agent`) |
   | `SA_APP_PASSWORD` | رمز مرحلهٔ ۳ (با فاصله یا بی‌فاصله) |

5. به ایجنت بگویید «تنظیم شد». ایجنت یک `ping` می‌فرستد و نتیجه را گزارش می‌کند.

**قطع دسترسی در هر لحظه:** کاربران ← همان کاربر ← «رمزهای عبور برنامه» ← «لغو». با این کار همهٔ دسترسی ایجنت فوراً قطع می‌شود.

> اگر `ping` با 401 برگشت، احتمالاً میزبان سرآیند `Authorization` را حذف می‌کند. اسکریپت سرآیند جایگزین `X-SA-Authorization` را هم می‌فرستد و قالب آن را می‌خواند. اگر باز هم 401 بود، فایروال یا CDN میزبان، مثلاً «حفاظت ربات»، درخواست‌های GitHub را می‌بندد و باید در پنل میزبان برای مسیر `/wp-json/sa-agent/` استثنا گذاشت.

## روش کار ایجنت (دستورها)

sandbox نشست Arena به sarzaminaryan.ir دسترسی شبکه ندارد. برای همین ایجنت کار را از راه **GitHub Actions** انجام می‌دهد. runner گیت‌هاب به سایت می‌رسد و رمزها را از Secrets می‌خواند.

### ۱) خواندن صفحه‌های عمومی (فوری و بدون رمز)

`fetch_page` روی `https://sarzaminaryan.ir/...` یا `https://sarzaminaryan.ir/wp-json/wp/v2/posts?slug=...`.

### ۲) خواندن کامل، پیش‌نویس و نوشتن (از راه فایل کار)

1. اگر متن لازم است، فایل HTML آن را در `tools/wp-agent/outbox/<slug>.html` بگذار.
2. یک فایل کار با نام یکتا بساز، مثلاً `tools/wp-agent/jobs/20261115-01-ping.json`:

   ```json
   {
     "note": "اتصال و دسترسی",
     "steps": [
       { "cmd": "ping" },
       { "cmd": "list", "type": "post", "status": "draft", "per_page": 20 }
     ]
   }
   ```

3. کار را روی شاخهٔ کاری بررسی کن و پس از تأیید مالک در `main` ادغام کن. workflow «WP agent» فقط با اجرای دستی از `main` و انتخاب یک فایل کار اجرا می‌شود؛ push شاخه و برنامهٔ زمان‌بندی‌شده اجرا را آغاز نمی‌کنند.
4. اجرا را دنبال کن و نتیجه را بخوان:

   ```bash
   gh workflow run wp-agent.yml --ref main -f job=tools/wp-agent/jobs/20261115-01-ping.json
   gh run list --workflow wp-agent.yml --limit 3
   gh run watch <run-id> --exit-status
   # نتیجه را از شاخهٔ main دریافت و بررسی کن
   cat tools/wp-agent/results/20261115-01-ping.json
   ```

- هر فایل کار فقط **یک بار** اجرا می‌شود؛ هم نتیجهٔ قبلی و هم journal مستقل می‌توانند اجرای تکراری را رد کنند. برای کار تازه نام یکتا بساز.
- مراحل یک کار به ترتیب اجرا می‌شوند و با اولین خطا یا رد، بقیه اجرا نمی‌شوند.

### وضعیت اجرا و بازیابی (محدودیت مهم)

`run-job` یک دفترچهٔ کوچک و قفل‌شده بیرون از checkout نگه می‌دارد: پیش‌فرض
`~/.local/state/sa-wp-agent/state.json`، یا مسیر مطلق `SA_WP_AGENT_STATE_DIR`.
این مسیر باید روی دیسک ماندگار باشد و تمام اجراکنندگان همان سایت از همان مسیر
و قفل فایل مشترک استفاده کنند؛ یک checkout یا دیسک موقت runner کافی نیست.
فایل فقط شناسهٔ کار، مرحله، وضعیت و شناسهٔ پشتیبان را ثبت می‌کند، نه رمز یا متن مقاله.

در شروع بعدی، کار تماماً خواندنی و بدون تغییر محتوا پس از crash قابل اجرای مجدد
است. اگر کار قبلی امکان نوشتن داشته یا نتیجهٔ restore نامعلوم باشد، اجرا متوقف
و تطبیق دستی لازم است؛ rollback خودکار پس از crash می‌تواند ویرایش‌های بعدی
افراد دیگر را بازنویسی کند. شناسهٔ پشتیبان و وضعیت در journal برای بررسی می‌مانند.
کارهای تمام‌شده هم برای جلوگیری از تکرار در journal ثبت می‌شوند.

**GitHub Actions فعلی از `ubuntu-latest` میزبانی‌شده استفاده می‌کند**؛ در آن
`run-job` عمداً بسته می‌ماند چون دیسک پس از اجرا از بین می‌رود. برای فعال‌سازی
باید ذخیره‌سازی پایدار و runner مناسب پیکربندی و اتصال آن end-to-end بررسی شود؛
صرف تنظیم یک مسیر روی runner موقت کافی نیست. تا آن زمان از اجرا روی production
استفاده نکنید. journal جایگزین ثبت پایدار و کامل گزارش نتیجه نیست.

### نمونهٔ مرحله‌ها

```json
{ "cmd": "get", "id": 1234 }
{ "cmd": "list", "type": "city", "search": "کاشان" }
{ "cmd": "draft", "type": "post", "title": "…", "content_file": "tools/wp-agent/outbox/kashan.html", "excerpt": "…", "category": ["travel"] }
{ "cmd": "draft", "type": "attraction", "title": "…", "content_file": "tools/wp-agent/outbox/x.html", "meta_file": "tools/wp-agent/outbox/x.meta.json" }
{ "cmd": "draft-copy", "id": 1234, "content_file": "tools/wp-agent/outbox/1234-rewrite.html" }
{ "cmd": "update", "id": 1234, "meta_file": "tools/wp-agent/outbox/1234.meta.json", "reason": "به‌روزرسانی شناسنامه" }
{ "cmd": "backups", "target": 1234 }
{ "cmd": "restore", "backup_id": 5678 }
{ "cmd": "theme-mods" }
{ "cmd": "theme-mods", "set": ["sa_show_featured=false"], "reason": "…" }
{ "cmd": "trash", "id": 153, "owner_approved_trash": true, "reason": "دستور مالک ۲۰۲۶-۱۱-۱۵: نسخهٔ تکراری پشت ۳۰۱" }
{ "cmd": "litespeed" }
{ "cmd": "litespeed", "set": ["crawler=true", "crawler-sitemap=https://sarzaminaryan.ir/wp-sitemap.xml"], "reason": "…" }
{ "cmd": "seo-scan", "workers": 4, "extra": ["/llms.txt"] }
{ "cmd": "probe", "url": ["/city/isfahan/", "/city/isfahan-city/"] }
```

- **فیلتر املا و نگارش (دستور مالک، ۱۶ نوامبر ۱۴۰۵):** هر `update`/`draft`/`draft-copy` پیش از ارسال از `replace_src/fa_lint.py` می‌گذرد — ماه میلادی و سال میلادی در متن فارسی، نیم‌فاصلهٔ جاافتاده، حروف/ارقام عربی، «ها»ی چسبیده پس از «ه»، واژه‌های ممنوع و واژهٔ لاتین بی‌جا نوشتن را رد می‌کنند (متن و متا). برای دیدن گزارش پیش از ساختن کار: `python3 tools/wp-agent/replace_src/fa_lint.py <dir|file>`؛ برای اصلاح قطعی `--fix`.
- `update` فقط برای متا یا برچسبِ نوشتهٔ منتشرشده آزاد است. تغییر عنوان یا متن آن را سایت با 409 رد می‌کند؛ از `draft-copy` استفاده کن.
- برای پیش‌نویس‌ها `update` متن را هم عوض می‌کند و پیش از آن پشتیبان می‌گیرد.
- `"owner_approved_live_edit": true` فقط با دستور صریح و مکتوب مالک در همان نشست مجاز است، و دلیل آن را در `reason` بنویس.
- `probe` (فقط خواندن، بی‌رمز) نشانی‌ها را بی‌دنبال‌کردن تغییر مسیر می‌خواند: کد وضعیت، `Location`، عنوان، canonical، robots، برچسب‌های `og:`/`twitter:`، و خودِ og:image را هم می‌گیرد (نوع، حجم، پهنا و بلندا). برای آزمودن ۳۰۱ها و کارت اشتراک‌گذاری پس از هر نصب.
- **قانون R4 (`inc/relations.php`):** شهرستان یا استانی که هنوز دیدنی/غذا/سوغات به آن وصل است به زباله‌دان نمی‌رود (پاسخ 500 با پیام «قانون R4»). اول وابسته‌ها را با `update` و متای `sa_city_id` به نسخهٔ اصلی وصل کن. **نکته:** تغییر متا کشِ روابط (۱۲ ساعت) را خالی نمی‌کند؛ هر تغییر وضعیت یک موجودیت (مثلاً زباله‌دانِ یک نوشتهٔ دیگر) آن را خالی می‌کند. نمونه: `jobs/20261115-07-repoint-trash-crawler.json`.
- `trash` (قالب ۲.۲۲.۷۴+) فقط نسخهٔ تکراری‌ای را می‌پذیرد که نشانی‌اش مبدأ یک قاعدهٔ `data/redirects.php` با مقصد منتشرشده است، و فقط با دستور صریح مالک.
- `litespeed --set` (قالب ۲.۲۲.۷۴+) فقط کلیدهای خزنده را می‌پذیرد؛ تنظیمات کش، CDN و بهینه‌سازی فقط خوانده می‌شوند.
- پیش از `theme-mods --set` به مالک بگو چه کلیدی از چه مقداری به چه مقداری می‌رود. در دورهٔ Core Update (تا حدود ۴ آذر ۱۴۰۵) تغییر ظاهری نده.

### ۳) اجرای مستقیم، اگر جایی شبکه به سایت برسد

مثلاً روی رایانهٔ مالک، با `.env` در ریشهٔ مخزن که هرگز commit نمی‌شود:

```bash
python3 tools/wp-agent/wp_agent.py ping
python3 tools/wp-agent/wp_agent.py get 1234
python3 tools/wp-agent/wp_agent.py draft --title "…" --content-file tools/wp-agent/outbox/x.html
python3 tools/wp-agent/wp_agent.py run-job tools/wp-agent/jobs/<name>.json
```

## فایل‌ها

- `wp_agent.py`: کلاینت. فقط کتابخانهٔ استاندارد پایتون را لازم دارد. رمز را هرگز چاپ نمی‌کند و در پیام‌های خطا با `***` می‌پوشاند.
- `jobs/`: فایل‌های کار ایجنت.
- `results/`: نتیجه‌ها. workflow آن‌ها را روی همان شاخه commit می‌کند. مخزن خصوصی است.
- `outbox/`: متن و متای آماده برای ارسال.
- `replace_src/county_page.py`: **ساخت صفحهٔ شهرستان از فایل داده** (قالب ۲.۲۲.۹۲). یک فایل `replace_src/data/<slug>.json` + `python3 replace_src/county_page.py <slug>` → سه فایل outbox؛ فیلتر املا، رجیستری قالب (`template.py`) و نگهبان (`check_template.py`) پیش از نوشتن اجرا می‌شوند.
- `replace_src/template.py`: رجیستری بخش‌ها (تنها جای تعریف چینش و تیتر)، `marked_body()` برای نشانگرهای `sa:sec` و `NEEDS` (بخش نقشه بدون `lat`/`lng` = صفحهٔ ناقص).
- `replace_src/theme_sources.py`: فهرست دامنه‌های منبع که قالب رندر نمی‌کند، خوانده‌شده از `inc/template-tags.php`؛ پانویس روی این دامنه‌ها ممنوع است.
- `.github/workflows/wp-agent.yml`: اجراکننده.
- سمت سایت: `inc/agent-bridge.php`. تست آن در `tests/test-agent-bridge.php` است.
