# tools/maps — نقشهٔ شهری قم و فارس به سبک deMAr

ابزار دوم نقشه در این پوشه. `make_province_maps.py` نقشهٔ تخت مرزی می‌سازد،
`make_province_3d.py` نقشهٔ ایزومتریک، و **این یکی نقشهٔ کارتایوگرافیک شهری**
می‌سازد — همان زبان بصری نمونه‌های deMAr: پهنه‌های رنگی، سلسله‌مراتب جاده و
قابِ عنوانِ حاشیه‌نویسی.

پیش‌فرض فقط **قم** و **فارس** است، در **دو مدل**.

## دو مدل

| مدل | زمین | جنگل/پارک | بافت شهری | جاده | قاب عنوان |
| --- | --- | --- | --- | --- | --- |
| `sand` | کرم `#ece6d6` | سبز زیتونی | بژ گرم | جوهر سیاه | مشکی |
| `ink` | آبی‌فام روشن | سبز خاکستری | نارنجی مرجانی | جوهر سرمه‌ای | نارنجی `#dd6230` |

هر دو مدل **هم خیابان‌های شهری و هم جاده‌ها** را می‌کشند، با سلسله‌مراتب ضخامت
جدا: بزرگراه ۳٫۴ ← تریانری ۱٫۰ ← خیابان مسکونی ۰٫۶۲ ← راه Service ۰٫۳۶.
بزرگراه و راه اصلی «کاسینگ» مشکی دارند و روی آن پرچم روشن کشیده می‌شود، دقیقاً
مثل نمونه‌ها.

## اجرا

```bash
python3 tools/maps/make_city_maps.py                      # قم و فارس، هر دو مدل
python3 tools/maps/make_city_maps.py --only fars --styles ink
python3 tools/maps/make_city_maps.py --size 16 20 --dpi 300   # برای چاپ بزرگ
python3 tools/maps/make_city_maps.py --check
python3 tools/maps/make_city_maps.py --refresh            # دوریز کردن حافظهٔ نهان
```

خروجی در `outputs/province-city/` است؛ در `.gitignore`.

## لایهٔ خیابان: Overpass

دادهٔ خیابان از **Overpass API** گرفته می‌شود (`out geom`، یک پرس‌وجو برای
`highway`، `landuse`، `natural`، `leisure`، `waterway`) و در
`~/.cache/sa-province-maps/streets/<slug>.json` کش می‌شود. سه نشانی به‌ترتیب
امتحان می‌شوند و هرکدام دو بار تلاش می‌کند.

اگر Overpass در دسترس نباشد (شبکهٔ بسته، فیلتر، DNS بلاک — مثل محیط CI یا
این sandbox) ابزار:

* یک هشدار واضح چاپ می‌کند،
* **فقط مرز شهرستان‌ها** را می‌کشد و پسوند `-nostreets` به نام فایل می‌زند،
* و بالای نقشه می‌نویسد `OSM STREET LAYER UNAVAILABLE — COUNTY BOUNDARIES ONLY`.

ابزار **هرگز جادهٔ ساختگی نمی‌سازد**. با `--require-streets` در نبودِ داده خطا
می‌دهد تا در خط تولید متوجه نشویم.

## گزینه‌ها

| پرچم | کار |
| --- | --- |
| `--only qom,fars` | استان‌ها (پیش‌فرض قم و فارس) |
| `--styles sand,ink` | مدل‌ها |
| `--out DIR` | پوشهٔ خروجی |
| `--size W H` / `--dpi N` | اندازهٔ بوم و وضوح |
| `--margin` | حاشیهٔ کادر نقشه |
| `--require-streets` | بدون Overpass خطا بده |
| `--refresh` | حافظهٔ نهان خیابان را دوباره بگیر |
| `--check` | فقط گزارش وضعیت |

## داده و مرزها

| | |
| --- | --- |
| مرز استان | `ssepehrnoush/Iran-geojson-map-boundaries` (ODbL) |
| مرز شهرستان | `hosseinhabibi2004/iran-geojson` — استخراج Overpass (ODbL) |
| خیابان/کاربری/پارک/آب | Overpass API، پرس‌وجوی همین ابزار |
| نام فارسی | `data/counties.php` مخزن |
| انتساب لازم | `© OpenStreetMap contributors · ODbL 1.0` |

هندسهٔ خیابان با همان تصویر معادل آلبرزِ `make_province_3d.py` تصویر می‌شود و
به مرز استان برش می‌خورد، پس با نقشهٔ سه‌بعدی هم‌مقیاس می‌ماند.

## تست

```bash
python3 -m pytest tests/test_city_maps.py -q
```

تست‌ها ساخت پرس‌وجو، تبدیل پاسخ Overpass به هندسهٔ تصویرشده، رندر هر دو مدل با
دادهٔ ساختگی، و رفتار «بدون خیابان» را پوشش می‌دهند.

# نمای شهری گرافیکی — `make_city_views.py`

ابزار دوم برای **نمای نزدیکِ شهرها** با همان حال‌وهوای دو مدل بالا، ولی بدون
لایهٔ جادهٔ واقعی: شبکهٔ خیابان **ترسیم‌شده (stylized)** است.

## چرا ترسیمی؟

گوگل‌مپ API عمومی برای استخراج ندارد و اسکرپ آن در این محیط در دسترس نیست؛
Overpass هم برای این ابزار مسدود است. پس تنها چیزی که واقعاً از داده گرفته
می‌شود **مرز شهرستان‌ها از OSM** است. الگوی خیابان، بلوک ساخت‌وسان، رود، کوه و
پهنهٔ سبز همه با بذرِ ثابت و بر پایهٔ مختصات واقعی مرکز شهر ساخته می‌شوند تا
حال‌وهوای شهر دربیاید، نه برای ناوبری.

روی خودِ تصویر با خط درشت نوشته می‌شود:
`STYLIZED STREET PATTERN — NOT SURVEY ACCURATE`.

## اجرا

```bash
python3 tools/maps/make_city_views.py                        # همهٔ شهرها، دو مدل
python3 tools/maps/make_city_views.py --only shiraz --styles ink
python3 tools/maps/make_city_views.py --list
python3 tools/maps/make_city_views.py --check
```

| گزینه | کار |
| --- | --- |
| `--only NAME,…` | شهرها: `shiraz`, `tabriz`, `dorud`, `hamadan`, `qom` |
| `--styles sand,ink` | مدل‌ها (همان پالت `make_city_maps.py` + لایهٔ کوه) |
| `--out DIR` | پوشهٔ خروجی (پیش‌فرض `outputs/city-views`) |
| `--size W H` / `--dpi N` | اندازهٔ بوم و وضوح |
| `--seed-offset N` | بذرِ متفاوت برای واریانتِ دیگرِ همان شهر |
| `--no-counties` | مرز شهرستان‌ها نکِشیده شود |
| `--list` / `--check` | فهرست شهرها / گزارش وضعیت |

## شهرهای تعریف‌شده

| نامک | شهر | استان | چیدمان | ویژگی |
| --- | --- | --- | --- | --- |
| `shiraz` | Shiraz | فارس | شطرنجی | دریاچهٔ مخابرات، باغ‌های شمال |
| `tabriz` | Tabriz | آذربایجان شرقی | شطرنجی | رود آجی‌چای، کوه سهند |
| `dorud` | Dorud | لرستان | دره‌ای | شهرِ کشیده میان دو رشته‌کوه |
| `hamadan` | Hamadan | همدان | شطرنجی | کوه الوند، منار گار |
| `qom` | Qom | قم | شطرنجی | کوه سرخه در غرب |

افزودن شهر فقط یک دیکشنری در `CITIES` است: مختصات مرکز، اندازهٔ کادر، زاویه و
تراکم شبکه، رود، کوه و برچسب‌های انگلیسی.

## چه چیزی واقعی است و چه چیزی نیست

| لایه | وضعیت |
| --- | --- |
| مرز شهرستان‌ها | **واقعی** — OSM، با برش به کادر شهر و خط‌چین |
| مختصات مرکز شهر | **واقعی** |
| خیابان، بلوک، پارک، رود، کوه | **ترسیمی** — بذرِ ثابت، بدون ادعای دقت |

## تست

```bash
python3 -m pytest tests/test_city_views.py -q
```

تست‌ها قطعی‌بودن بذر، شکل بلوک‌ها و خطوط، مرزهای درون‌کادری، لایه‌های صحنه،

یا `make_city_maps.py` را روی سیستم متصل به اینترنت اجرا کن (Overpass واقعی)،
یا اسکرین‌شات گوگل‌مپ با نوار مقیاس بده تا هندسه از روی آن بازساحی شود.

# رَردیابِ اسکرین‌شات — `trace_maps_screenshots.py`

`make_city_maps.py` به اینترنت نیاز دارد و در این محیط در دسترس نیست؛
`trace_maps_screenshots.py` راهِ جایگزین است: **اسکرین‌شات گوگل‌مپ را محلی پردازش
می‌کند** و هندسهٔ واقعیِ خیابان‌ها، پهنهٔ ساخت‌وسان، پارک، آب و خطِ مرزِ قرمزِ
شهرستان را از روی رنگِ پیکسل‌ها بیرون می‌کشد.

```bash
python3 tools/maps/trace_maps_screenshots.py --list DIR_SCREENSHOTS \
    --out-dir outputs/traced --dpi 150
python3 tools/maps/trace_maps_screenshots.py shot.jpg --metres-per-px 20
```

| گزینه | کار |
| --- | --- |
| `--list DIR` | همهٔ تصاویرِ یک پوشه |
| `--out-dir DIR` | پوشهٔ خروجی (پیش‌فرض `outputs/traced`) |
| `--json PATH` | ذخیرهٔ ساختارِ برداریِ ردیابی‌شده |
| `--metres-per-px N` | مقیاسِ دستی؛ بر جدولِ `SCALE_BARS` مقدم است |
| `--dpi` / `--title` / `--subtitle` | اندازه و متنِ پوستر |
| `--no-render` | فقط ردیابی، بدون رندر |

خروجی برای هر تصویر یک جفت `sand`/`ink` است با نامی از مهرِ زمانیِ اسکرین‌شات،
مثلاً `traced-shiraz-07-23-20-sand.png`.

## خط لولهٔ ردیابی

| مرحله | کار |
| --- | --- |
| `classify` | تفکیک رنگ به جاده (آبی‌خاکستری)، آب، پارک، مرزِ قرمز و حذفِ هستهٔ متنِ برچسب‌ها |
| `clean_roads` | حذفِ دکمه‌ها و آیکن‌های رابط کاربری با معیارِ پهنا، نه بیشینهٔ مؤلفه |
| `vectorise_roads` | اسکلت‌سازی و تبدیل به خط، با عرضِ واقعی که ردهٔ جاده را می‌سازد |
| `urban_mask` | بافتِ ساخت‌وسان از بلوک‌های روشنِ خنثی (زمینِ بیرون شهر بژ است) |
| `trace_boundary` | اتصالِ نقطه‌های قرمزِ مرز به یک حلقهٔ بسته |
| `render` | پوسترِ کاغذ-شبیه‌نقاشی با مقیاسِ واقعی، شمال‌بالا و یادداشتِ منشأ |

مختصاتِ برداری **شمال‌بالا و بر حسب متر** است (مبدأ: گوشهٔ بالا-چپ کادرِ نقشه).

## مقیاس

مقیاسِ هر تصویر از نوارِ مقیاسِ خودِ گوگل در همان اسکرین‌شات خوانده شده و در
`SCALE_BARS` ثبت است: تصاویرِ `۰۷-۲۲-۴۵` و `۰۷-۲۲-۵۲` نوارِ ۱۰ کیلومتری روی
۲۲۴ پیکسل دارند، و چهار تصویرِ نزدیکِ `۰۷-۲۳-۰۶` تا `۰۷-۲۳-۲۰` نوارِ
۵ کیلومتری روی ۲۵۰ پیکسل (هم‌بزرگ‌نمایی، با هم‌ترازیِ هم‌پوشانی تأیید شده).

## چه چیزی واقعی است و چه چیزی نیست

| لایه | وضعیت |
| --- | --- |
| خیابان‌ها، پهنهٔ ساخت‌وسان، پارک، آب | **واقعی** — ردیابیِ پیکسلیِ گوگل‌مپ |
| مرز شهرستان | **واقعی** — خطِ قرمزِ خودِ گوگل‌مپ |
| برچسب‌ها، آیکن‌ها، دکمه‌های رابط کاربری | حذف‌شده یا ناقص؛ پوستر برای نمایش است، نه مسیریابی |
| انتساب | `© OpenStreetMap contributors` · ODbL 1.0 (داده‌های OSM که در تصویر دیده می‌شوند) |

روی هر پوستر این هشدار چاپ می‌شود:
`GEOMETRY TRACED FROM GOOGLE MAPS SCREENSHOT — NOT FOR NAVIGATION`.

جاده، ردیابیِ پارک/آب/مرز، شمال‌بالا بودن بردار، قطعی‌بودن، یادداشتِ منشأ،
